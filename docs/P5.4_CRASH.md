# P5.4 — Crash report to SD (2026-10-12, 2026-10-16)

## Landed

- Switch user-exception handler (`__libnx_exception_handler`) writes a
  readable text report to **`sdmc:/switch/dw3/crash_report.txt`**.
- Report fields: port version, reason, **`mode_file`** / **`stage_file`**
  (last restored mode overlay and sub-overlay / stage id), **`vsync_pumps`** /
  **`last_dt_us`** (frame-loop progress noted from the vsync pump, landed
  2026-10-16), PC / LR / SP / FAR / ESR, and a pointer at `dw3.log`.
- Sink is opened on the main thread at boot (`dw3_nx_crash_install` from
  `boot_main.c` after SD mount + log open). Handler I/O uses libnx
  `fsFileWrite` (no stdio lock). Soft default: handler always linked;
  **no forced fault** in release / preview NROs.
- **Startup latch (2026-10-16):** install rotates a report left over from
  the previous run to `sdmc:/switch/dw3/crash_report_prev.txt` (one kept)
  and logs `previous run crashed: version=… reason=… mode_file=…
  stage_file=…`, so repeating a crash no longer eats the previous copy.
  Archival copies stay the owner's evidence flow.
- After the SD write, the handler `svcBreak`s so Atmosphere creport can
  still capture the fault under `sdmc:/atmosphere/crash_reports/`.
- Sub-overlay latch: `dw3_overlay_current_sub_file()` in `port/overlays`
  (mode latch unchanged for the mesh gate).
- Options / mechanism notes (kernel path, Atmosphere creport + fatal, data
  to capture, why a periodic marker file is not it):
  [P5.4_ERROR_REPORT.md](P5.4_ERROR_REPORT.md).

## How to force a fault (debug build)

Soft default is **off**. The build script passthrough (`--force-crash`,
landed 2026-10-16) makes the smoke build one command:

```bash
./tools/build_switch_game.sh --nxlink --force-crash
```

The CMake option `DW3_NX_FORCE_CRASH` still works when configuring directly
(Docker/`tools/dk.sh` on this host):

```bash
./tools/dk.sh bash -c 'cmake -S platforms/switch -B /tmp/dw3-force-crash -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE=/opt/devkitpro/cmake/Switch.cmake \
  -DDW3_NXLINK_STDIO=ON -DDW3_NX_FORCE_CRASH=ON && \
  cmake --build /tmp/dw3-force-crash -j"$(nproc)"'
```

Or set the cache entry in an existing nxlink build dir and rebuild:

```bash
cmake -B build/switch-nxlink -DDW3_NX_FORCE_CRASH=ON
cmake --build build/switch-nxlink -j"$(nproc)"
```

Boot that `.nro` once. After path init it deliberately null-writes; pull
`sdmc:/switch/dw3/crash_report.txt` over FTP / USB and confirm it names
`user exception`, registers, `vsync_pumps` / `last_dt_us`, and `mode_file` /
`stage_file` (often `0x0` if the fault is before any overlay restore). Reports
written by preview.29 count two pumps per VSync (fixed after it): halve its
`vsync_pumps`, and its `last_dt_us` spans 30 frames, not 60. A
fresh Atmosphere report under `sdmc:/atmosphere/crash_reports/` is expected
too. On the *next* boot, `dw3.log` gains the `previous run crashed:` latch
line and the old report is kept as `crash_report_prev.txt`.
[PREVIEW26_CRASH_RECORDS.md](PREVIEW26_CRASH_RECORDS.md) already shows both
mechanisms producing files after real (unforced) crashes on the OLED.

Software-only report without a CPU fault (for host unit checks later):

```c
dw3_nx_crash_write_report("manual smoke");
```

## Done when

A forced fault produces a readable report on SD — verified by the
`DW3_NX_FORCE_CRASH` path above on hardware or Ryubing with a mirrored
`sdmc:`.
