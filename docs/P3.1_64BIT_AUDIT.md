# P3.1 — 64-bit audit (overlays + stages)

**Status:** done on `phase3-pc-bringup` via match-neutral patch
`port/patches/0018-match-neutral-overlay-64bit-audit.patch`.

## Scope

Same class of fixes as P2.4, applied under `src/field`, `src/battle`,
`src/cardgame`, `src/menus`, `src/debug` (plus `include/engine/gfx.h` for
`vsyncArg`):

- Literal `createTask` / `createTaskWithId` sizes → `sizeof(...)`
- Pointer-slot `childrenSize` → `N * sizeof(Task *)` / `STAGE_CHILDREN_SIZE`
- Stage select save mode arg → `STAGE_SELECT_MODE_ARG_SAVE` (`-0x80000000`)
- Task pointers stored as `void *` (scripts, `GFX.vsyncArg` / `vsyncFunc`)
- Archive / face / fighter list address math → pointer + offset (no
  `(s32)ptr`)

## Evidence

1. `tools/apply_patches.sh --check` passes with `0018` in the series;
   `vendor/dw3_decomp` stays clean.
2. After apply, no remaining literal size args in the five audit dirs:
   `rg 'createTask(WithId)?\([^,]+,\s*(0x|\[0-9\])' …` → empty for
   non-`sizeof` forms (debug stubs use `sizeof(StageSelect)` /
   `sizeof(Task)`).
3. Representative TUs compile with
   `-Werror=pointer-to-int-cast -Werror=int-to-pointer-cast
   -Werror=int-conversion`:
   `stage_select.c`, `map.c`, `event.c`, `script.c`, `cursor.c`,
   `fighter_info.c`, `normal_battle/menu.c`, `wstag780.c`, `wstag810.c`.
4. Linked Phase 2 units still build: `ninja -C build/pc dw3_engine_objs`
   (engine + title) succeeds under the same warning-as-error flags in
   `port/CMakeLists.txt` `_DW3_GAME_OPTS`.

Full overlay object libraries (every stage `.c`) are deferred to P3.2+
when those TUs are linked; any new cast diagnostics found then get
follow-up patches.
