# P6.1 widescreen: menu and transition audit

Date: 2026-10-15. Base: `main` at `8d62d55` (#158). Question: which menu
screens and transition effects are adapted for widescreen, which are not,
and what each one needs. Companion to [P6.1_WIDESCREEN.md](P6.1_WIDESCREEN.md).

## How a scene gets widescreen

Policy lives in `port/options/widescreen.c` (`dw3_port_widescreen_px`). It is
keyed on the **current mode overlay file** only:

| Overlay | US file | EU file | Gutter per side |
|---|---|---|---|
| `FIELDSTG` | 0x158 | 0x166 | 53 px |
| `FIGHTSTG` | 0x159 | 0x167 | 53 px |
| `STSTATUS` (field menu) | 0x1F9 | 0x207 | 53 px |
| `STITSHOP` (item shop) | 0x1F7 | 0x205 | 53 px |
| `STGMCARD` (memory card) | 0x1E3 | 0x1EE | 53 px |
| `STDGNAME` (partner name) | 0x154 | 0x162 | 53 px |
| every other overlay | | | 0 (4:3) |

So an overlay is either all-widescreen or all-4:3: nothing inside a mode can
opt out. Inside a widescreen overlay the game's own 320-wide UI stays where it
is; what changed is (a) the renderer draws gutters, (b) patches 0048-0053 fill
the gutters (map, mesh culling, full-screen fades, 96-px menu background
pattern). The menu background fill works because four menus draw one sprite
that repeats every 96 px (`bgScroll`); patch 0053 draws it twice more.

Adding an overlay to the list is one line in `widescreen.c`, but unless it
also fills the gutters (patch 0053 style) the gutters are black strips, which
is worse than pillarboxing. So "adapt" below means list entry plus a fill.

## What is not applicable or not found

- No standalone "Digivice", evolution/DV, bank or naming-keyboard overlay
  exists in the decomp: they are screens inside `STSTATUS`, `STGDGLAB`,
  `STDGNAME`, `STPLNMET` or `FIGHTSTG` and take that overlay's state.
- No screen was found that is *stretched* (picture scaled non-uniformly). The
  failure modes are pillarbox (whole overlay), letterbox (a 320 band inside a
  widescreen overlay) and cut panel ends.

## Prioritized next steps

By player visibility, then effort (E = effort, V = visibility).

1. **Battle report (`STFGTREP`)** - V high (after every battle), E low. Add
   0x1400 (EU id from `overlay_host` tables) to `widescreen.c`, two extra
   `sprite.draw` calls at `bgScroll` +/-96 in `report.c:45`. Removes the
   16:9 -> 4:3 -> 16:9 flicker around each fight.
2. **Gym and Digimon Lab (`STGTRAIN`, `STGDGLAB`)** - V medium, E low. Same
   recipe at `gym/screen.c:337` and `digimon_lab/lab.c:101`; check the gym
   result sprites that use `setPivot(0x140,..)`. Then the card shop
   (`card_packs/shop.c`, scroll period 0x60) if its sprite repeats.
3. **Area name banner and iris wipe** - V high (every warp), E medium/low.
   Banner done (patch 0071, 2026-10-23). Still open: start the
   `closeField` iris at the gutter-wide rectangle and widen its grid cover
   (captured 2026-10-23: the gutters snap to black, the grid is 320 wide).
4. **Encounter transition** - V high (every battle), E medium-high. Decide
   between black gutters with a 4:3 swirl (zero work) or gutter-aware tiles.
   Needs a real capture of the transition on all three hosts.
5. **Player name entry (`STPLNMET`)** - V medium (new game only), E medium.
   Needs wider backdrop art than the two 320-px scrolling sprites.
6. Cut panel ends in the four adapted menus, world map screen, Switch title
   backdrop, deck editor/album - V low-medium, each needs a look first.
