# P4.6 Modules on Switch — dynamic loading not required

Status: **decision recorded, no code needed** (2026-10-10). ROADMAP P4.6 stays
open: its done-when ("all overlays switch on hardware") is a hardware check,
not a code gap.

## Question

PSY-Z exposes a module API to simulate PS1 overlays as dynamic objects:
`Psyz_ModuleOpen` / `Psyz_ModuleClose` (`vendor/psyz/psyz/include/psyz/module.h`,
backends in `src/platform/module_{unix,win}.c` and
`src/psp/psp_module_host.c`). libnx has no `dlopen`. Does the Switch port have
to provide a static `Psyz_ModuleOpen` dispatch table?

## Answer: no

| Evidence | Where |
|---|---|
| The only reference to `Psyz_ModuleOpen` / `Psyz_ModuleClose` / `psyz/module.h` anywhere in this repo is the (former) `nx_module.c` stub itself — no caller in `port/`, `tools/`, `platforms/`, or the decomp. | repo-wide grep |
| The decomp never loads modules. `loadModeOverlay` / `loadSubOverlay` are a pure `memcpy` on PS1; under `PORT_HOST` (patch `0008`) they call `dw3_overlay_restore` instead. | `vendor/dw3_decomp/src/engine/system/overlay.c`, `port/patches/0008-PORT_HOST-static-overlay-restore.patch` |
| P2.6 links every overlay into one image; "load" is `.data` restore + `.bss` zero keyed on the tracked id. The Switch CMake reuses that static model (`--whole-archive` overlay libs + `-Wl,--undefined=__start_dw3data_*`). | `port/overlays/`, `platforms/switch/CMakeLists.txt` |
| The Switch boot path already registers the table (`dw3_overlay_register_us_title()`). | `platforms/switch/source/boot_main.c` |
| PSY-Z's `NintendoSwitch` CMake branch compiles **no** module source — comment: *"there is no SDL and no dlopen"*. | `vendor/psyz/psyz/CMakeLists.txt` |
| The linked PC game image has **zero** `Psyz_Module*` symbols (`nm build/pc/dw3-pc`): even on Linux, where `module_unix.c` exists, the static archive member is never pulled in because nothing references it. | `build/pc/dw3-pc` |
| P4.7's Switch link reports 0 undefined symbols at 1144 objects — no missing `Psyz_Module*`. | `docs/SWITCH_BACKEND.md` |

Adding an `nx_module.c` implementation would export a symbol PSY-Z itself does
not provide on this target, for a caller that does not exist. The file is
therefore an intentionally empty translation unit documenting the decision
(see its header comment).

## Still pending (why P4.6 is not ticked)

The done-when is "all overlays switch on hardware". That needs:

- a Switch (or a Ryubing session trusted for overlay switching) to enter modes
  whose overlay id changes, and confirm globals reset on change / are preserved
  on same-id re-entry;
- the same evidence the PC fixture already gives
  (`tools/tests/test_overlay_host.py`), but observed through the Switch build.

No Switch hardware in the sessions so far; this is the only blocker, and it is
shared with P4.2 / P4.3 / P4.7.

## Validation performed for this decision

- PC host build (`build/pc/dw3-pc`) links with no `Psyz_Module*` reference.
- `python3 -m pytest tools/tests` — host overlay/static-model tests.
- `.nro` build not run here (no Docker daemon on this host); see
  `docs/SWITCH_BACKEND.md` for the devkitPro CI path.
