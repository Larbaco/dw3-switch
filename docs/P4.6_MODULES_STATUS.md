## Question

PSY-Z exposes a module API to simulate PS1 overlays as dynamic objects:
`Psyz_ModuleOpen` / `Psyz_ModuleClose` (`vendor/psyz/psyz/include/psyz/module.h`,
backends in `src/platform/module_{unix,win}.c` and
`src/psp/psp_module_host.c`). libnx has no `dlopen`. Does the Switch port have
to provide a static `Psyz_ModuleOpen` dispatch table?

## Answer: no

| Evidence | Where |
|---|---|
| The only reference to `Psyz_ModuleOpen` / `Psyz_ModuleClose` / `psyz/module.h` anywhere in this repo is the (former) `nx_module.c` stub itself — no caller in `port/`, `tools/`, `platforms/`, or the decomp. | repo-wide grep |
| The decomp never loads modules. `loadModeOverlay` / `loadSubOverlay` are a pure `memcpy` on PS1; under `PORT_HOST` (patch `0008`) they call `dw3_overlay_restore` instead. | `vendor/dw3_decomp/src/engine/system/overlay.c`, `port/patches/0008-PORT_HOST-static-overlay-restore.patch` |
| P2.6 links every overlay into one image; "load" is `.data` restore + `.bss` zero keyed on the tracked id. The Switch CMake reuses that static model (`--whole-archive` overlay libs + `-Wl,--undefined=__start_dw3data_*`). | `port/overlays/`, `platforms/switch/CMakeLists.txt` |
| The Switch boot path already registers the table (`dw3_overlay_register_us_title()`). | `platforms/switch/source/boot_main.c` |
| PSY-Z's `NintendoSwitch` CMake branch compiles **no** module source — comment: *"there is no SDL and no dlopen"*. | `vendor/psyz/psyz/CMakeLists.txt` |
| The linked PC game image has **zero** `Psyz_Module*` symbols (`nm build/pc/dw3-pc`): even on Linux, where `module_unix.c` exists, the static archive member is never pulled in because nothing references it. | `build/pc/dw3-pc` |
| P4.7's Switch link reports 0 undefined symbols at 1144 objects — no missing `Psyz_Module*`. | `docs/SWITCH_BACKEND.md` |

Adding an `nx_module.c` implementation would export a symbol PSY-Z itself does
not provide on this target, for a caller that does not exist. The file is
therefore an intentionally empty translation unit documenting the decision
(see its header comment).

## What "all overlays switch on hardware" means

Modes and stages are **already linked** into the Switch game image (P3.2–P3.8
/ P4.7). P4.6 is not a link gap. The remaining work is an **evidence path**:

1. Confirm restores happen when the tracked mode / sub id **changes**.
2. Confirm no `UNKNOWN` restore for a linked overlay the player actually enters.
3. Keep same-id **preserve** covered by the PC fixture
   (`tools/tests/test_overlay_host.py` + patch `0008`); hardware proves the
   restore side that preview logs only sampled informally.

Battle GPU / mesh (`nx_mesh`, `switch_gpu`, DIAG) is **out of scope** for this
item. Soft or mesh battle picture quality does not block P4.6 if
`FIGHTSTG` / `WFIGHTMN` / `STFGTREP` / return-`FIELDSTG` restore lines appear.

## Nxlink markers (any `--nxlink` or stdio build)

| Line | Meaning |
|---|---|
| `dw3: registered US overlays … count=N` | Static table installed at boot |
| `dw3: overlay restore file=0x… kind=mode …` | Mode overlay `.data` restore + `.bss` zero |
| `dw3: overlay restore file=0x… kind=sub …` | Sub-overlay / stage restore |
| `dw3: overlay restore file=0x… kind=unknown UNKNOWN` | **Fail** — id not in the linked table |
| `dw3: ERROR overlay restore failed: file=0x… (<dec>): <reason>` | Follows every `UNKNOWN` line (patch `0061`); the id is not recorded as loaded. A replay build then prints `dw3: FATAL …` and aborts |
| `dw3: mode=…` / `FIELDSTG_pickStage … stageFile=` | Companion decomp lines (optional) |

Same-id skips intentionally produce **no** restore line (patch `0008`). Do not
add per-frame keep spam. Preserve semantics stay on the host fixture unless a
future rare-event keep marker is justified.

Older builds omit `kind=`; `tools/parse_overlay_nxlink.py` still parses them.

## Owner OLED checklist

Build: `./tools/build_switch_game.sh --nxlink` →
`build/switch-nxlink/dw3-switch-nxlink.nro`. Launch with hbmenu **Y** NetLoader
and `nxlink -a <IP> -s …` (see `docs/NXLINK_DEBUG.md`). Capture the nxlink
stdio (or copy `sdmc:/switch/dw3/dw3.log` after).

Parse:

```bash
python3 tools/parse_overlay_nxlink.py path/to/nxlink-capture.txt
# or:
nxlink -a <IP> -s … 2>&1 | tee /tmp/dw3-p46-oled.log
python3 tools/parse_overlay_nxlink.py /tmp/dw3-p46-oled.log
```

| # | Player action (US) | Expect restore names (US file ids) | ☐ |
|---|---|---|---|
| 0 | Boot to title | `registered US overlays` + `STDWTITL` (`0x1C1`, kind=mode) | ☐ |
| 1 | New Game → name entry | `STPLNMET` (`0x1F8`) | ☐ |
| 2 | Finish name → Kusanagi street | `FIELDSTG` (`0x158`) + `WSTAG780` (`0x1DA`, kind=sub) | ☐ |
| 3 | Door / map change (e.g. Online Center) | New stage id ≠ `0x1DA` (e.g. `WSTAG785` `0x1DB`) | ☐ |
| 4 | Enter battle | `FIGHTSTG` (`0x159`) + `WFIGHTMN` (`0x1FA`) | ☐ |
| 5 | Win / report | `STFGTREP` (`0x1C2`) | ☐ |
| 6 | Return to field | `FIELDSTG` (`0x158`) again | ☐ |
| 7 | Optional: field menu / shop / card | `STSTATUS` / `STITSHOP` / `CARDGAME` / … as entered | ☐ |
| 8 | Whole capture | **Zero** `kind=unknown UNKNOWN` lines | ☐ |

**Pass rule for ticking ROADMAP P4.6:** steps 0–6 and 8 checked on hardware,
parser reports checklist PASS (or equivalent manual grep), and a short owner
note (build / preview tag + date) is pasted under **Hardware evidence** below.
Step 7 is stretch; full P3.8 stage count is **P5.5**, not P4.6.

**Do not tick** from preview.4/7 informal “battle worked” alone — those runs
prove field/battle exist, not this restore sequence.
