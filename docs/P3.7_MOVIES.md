## Runtime pack (P1.6)

Owner `runtime/us` has 13 `.STR` files under `AAA/STR/`. Map marks
`form: 2`. `pack_runtime.py` copies the AAA tree as-is (2048-byte extracts).

A 2048-byte sector keeps 16 of the 18 XA ADPCM blocks. The decoder still
emits 18, so the missing pair is silence and the soundtrack runs long
(opening movie: 120.6 s of picture at CD 2×, 12.5% slow audio).
`tools/restore_form2_str.py` rewrites each STR as raw Mode2/2352 from the
disc image. The game does the same on startup (`port/movies/str_restore.c`)
when `DW3_DISC_BIN`, `DW3_DISC_CUE`, or a BIN/CUE next to the runtime (or
in its parent) is present. `boot_tim.bin` in the runtime root is not a
disc image. A CUE `FILE` name that does not match the BIN still works
when that directory has one other `.bin` large enough to cover the STRs. `str_stream` uses that stride when
`file size == sectors * 2352`. The 2048 path remains, and `DW3_DISC_BIN`
still fills the tail for a file that was not rewritten.

On Switch that first rewrite used to clear a static dark blue, so the
copy looked frozen. The progress hook now passes bytes written this run
and the total of form-2 STR extents that still need a rewrite.
`boot_main.c` fills a bar from that fraction about every 300 ms, and
also when a file starts or finishes. Before the first byte the track
shows a sweep. The PC host still only logs. This bar was not run on an
OLED.

**Sector adapter (Wave 3–4):** for a 2048 pack, `port/movies/str_stream.c`
synthesizes Mode2/Form2 **2352-byte** sectors (sync + header + subheader +
2048 user + zero pad). PSY-Z `StCdInterrupt` reads user data at offset 24.
Video magic `0x0160` → submode Data|Form2|RT; non-video (XA ADPCM) →
Audio|Form2|RT + stereo CI `0x01`.

**Picture clock:** `Psyz_CdPumpStream` used to hand the ring 8 sectors per
call, and both VSync and `StGetNext` call it, so a 15 fps / ~10-sector
frame finished every display frame. The pump now follows PS1 double-speed
(150 sectors/s). XA is pulled by the mixer at 37800 Hz, which matches that
sector rate when all 18 ADPCM blocks are present.

Measured evidence for the pace on PC and on the OLED — and why the Switch
wait loop is `StGetNext`-bound — is in
[`P3.7_MOVIE_PACING_DIAGNOSTICS.md`](P3.7_MOVIE_PACING_DIAGNOSTICS.md).

## Task 5 — Sustained play + Start-skip (2026-10-10)

### Root cause (stall after ~3 frames)

`StSetRing(..., 32)` holds ~3×9-sector MOVIEOPN frames. When the ring
could not accept the next video sector, `StCdInterrupt` called
`stream_consume_sector()` anyway — **dropping** STR sectors and breaking
`secCount` sequencing. `StGetNext` then starved inside
`STDWTITL_decodeNextFrame` (busy-wait ≈ `0x800000` / ~180s wall; often
described as `waitFrameDecoded`). Start-skip never reached the pad check.

### Fix

PSY-Z `libcd.c`: on ring-full / wrap-blocked, **return without advancing**
CD position (backpressure). `Psyz_CdPumpStream` stops the sector loop when
a pump call makes no progress. Host `psyz_dma_present.c` logs more
`DecDCTout frame done` milestones.

### Glitch B — solid gray picture (fixed)

Even at full width, FB dumps were flat mid-gray (`uniq8≈1`, `RGB≈128/132`).

**Two stacked bugs:**

1. **STR ring wrap sentinel missing** in PSY-Z `StCdInterrupt`: when the write
   index wraps, Sony sets `id=1` so `StGetNext` resets `StRingIdx3` to 0. Without
   it, after ~3×9-sector MOVIEOPN frames `decodeNextFrame` starves and the player
   **replays the same VLC buffer** forever (only ~3 `DecDCTvlc2` calls while
   `DecDCTout` keeps climbing). bsdec looked “DC+EOB only” because fc=1 is a
   real fade-in and fc=2–3 still letterbox the first slices.
2. **No default MDEC quant/IDCT** after `Psyz_MdecReset`: game only calls
   `DecDCTReset(0)`. With `quant[i]==0`, AC×q becomes 0 → unsigned mid-grey.

bsdec itself is fine offline (`fc=30` → `ac_blocks≈2525` / `ac_coeffs≈18k`).

**Fixes:** ring `id=1` sentinel in `vendor/psyz/.../libcd.c`; host
`__wrap_DecDCTReset` → `DecDCTGetEnv`+`DecDCTPutEnv`. `DW3_VLC_LOG=1` logs
`ac_blocks`; default `DW3_FB_DUMP` at frame **#30** via VRAM dump.

```bash
SDL_VIDEODRIVER=offscreen SDL_AUDIODRIVER=dummy \
  DW3_START_MODE=0xE01 DW3_RUNTIME=runtime/us DW3_VLC_LOG=1 \
  DW3_FB_DUMP=build/movie-evidence/video-ac.ppm \
  timeout -s KILL 25 ./build/pc/dw3-pc --runtime runtime/us
# expect: DecDCTReset → PutEnv default quant/IDCT
# expect: dw3-vlc frame#30 ac_blocks≫0; VLC count ≫3
# expect: RGB24 LoadImage #581 uniq8≫1; FB dump uniq≫1 (not flat grey)
```

Do **not** confuse with P3.6 libsnd / midiread work.

### Glitch C — macroblock garbage after A/B (fixed on `phase3-gpu-glitch`)

Geometry + AC metrics looked fine, but FB dumps were unrecognizable.
Offline `bsdec` + soft MDEC of the same BS produced a clean eye/Agumon
frame. Root causes:

1. **LP64 `MDEC_in`:** `DecDCTPutEnv` casts `u32 mdec_iq[]` to `u_long *`,

2. **Sync slice double-buf:** `onSliceDecoded` nested `DecDCTout` before

## Switch (2026-10-10)

Same four host pieces as the PC present, in
`platforms/switch/psyz_backend/nx_present.c`: MDEC-out `DMACallback`,
RGB24 `LoadImage` / `PutDispEnv`, `DecDCTReset` quant+IDCT upload, and the
slice stash. PSY-Z's `DMACallback` is still a no-op, so without the wrap
the title player waits forever, XA keeps going, and the movie rect stays
empty.

24-bit mode presents 480 lines. The title does not: an early `PutDispEnv`
can set the 480-line bit with `disp.h=640` while `isrgb24` is still clear,
and `SetDefDispEnv` leaves `screen.h` at 0 so the vertical range stays 240.
Height follows the vertical range unless `Draw_SetDisplayMode` says rgb24.

One Switch-only stall remained after the slices were uploading. `StGetNext`
only looks at `StRingAddr[StRingIdx3]`. That cursor can land on a body
sector (`id == 3`, `secCount > 0`) whose header (`id == 2`) is
`secCount` slots earlier, or on a leftover tail after the header was
reused. The writer then refuses to overwrite the slot and the player
replays the last VLC. `__wrap_StGetNext` steps back onto the matching
header, or clears an orphan tail and scans for the next `id == 2` / `id == 1`.
Ryubing: `DecDCTout frame done` keeps climbing (signatures change), the
present alternates the two 320×480 movie buffers, the attract loop returns
to the title, and the next loop shows the Bandai card. That 320x480
present was the intermediate log. The current sample is 416 lines at
VRAM y=36 (`docs/SWITCH_BACKEND.md`). P4.7 was later ticked on an OLED
menu boot.
