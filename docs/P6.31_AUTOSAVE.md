Status (2026-10-27): **rebuilt as a separate file after the owner's decision of
2026-10-26; PC US and EU replays pass; owner OLED check open.** Branch
`feat/p6.31-autosave-file`. First slice (2026-10-25, PR #260): the auto-save
wrote over the card slot last used. That is gone.

## Owner decisions (2026-10-26)

1. **The auto-save never overwrites the player's slots.** It is its own file,
   `autosave.bin`, in the card folder.
2. **The title screen's Continue loads the auto-save; the old Continue (the
   slot list, STGMCARD) is now Load.** This applies **whenever an auto-save
   file exists, regardless of the Auto-save option** (default chosen, owner can
   change: the option only decides whether new auto-saves are written; a file
   written earlier is still offered).
3. **With no auto-save file the title has four plaques and the third reads
   Load Game** (owner decision 2026-10-28, replacing the 2026-10-26 default
   under which the third plaque still said Continue; the owner found a
   "Continue" that opens a slot list confusing). New Game, Options, **Load Game**
   (opens the slot list), Quit game. With the file: New Game, Options,
   **Continue** (loads `autosave.bin`), **Load Game** (the slot list), Quit
   game. The US disc already read Load Game on the third plaque; the EU disc's
   own sprite there said "Continue" (Continue / Continuer / Weiter / Continua /
   Continuar), so on EU the plaque is the port's Load Game lettering in the five
   languages (Load Game / Charger / Laden / Carica / Cargar, the words of the
   row that appears beside Continue). The words of Continue come from the disc
   (Continue, Continuer, Weiter, Continua, Continuar).
4. Once progress is 4 or more and the map is known, an area change writes it.
   A **new game overwrites the previous auto-save** (default chosen, owner can
   change; there is one auto-save, not one per game).

## What it is

An Options row, **Auto-save**, OFF (default) or **Each area**. With it on, the
first idle frame of every new field area writes the game to `autosave.bin`.
With it off nothing is read, written or logged by the field hook.

`autosave.bin` is a normal flat card file (the P5.3 format: header, icons, info
section at `0x200`, data slots from `0x300`), 32 KiB, with the game's save in
slot 0 and the other two summaries empty. The existing fill code is reused: the
bytes are what `STGMCARD_fillSave` builds (the game's save bytes, the XOR
checksum from byte 4, the region's version byte) and the same 0x44 summary
(name, area, place, money, play time, party). It is rename-atomic like
`save<N>.bin` (tmp, fsync, remove, rename; a leftover tmp is recovered at boot).
`save0.bin` and `save1.bin` are never written by it, and the old
`save<N>.bin.pre-auto` copy logic is gone (old `.pre-auto` files are left alone).
The cheat mark sidecar is `autosave.cheats` (see below).

## Title menu

With an auto-save file (and the native overlay, i.e. PC SDL3 GPU and the
Switch) the title shows **five** plaques:

| Row | Label | Does |
|---|---|---|
| 0 | New Game | as before |
| 1 | Options | as before |
| 2 | **Continue** | loads `autosave.bin` straight into the game (no slot list) |
| 3 | **Load Game** (the port's own lettering in five languages: the EU disc's own label for this row says "Continue") | the old Continue: card choice, slot list, load |
| 4 | Quit game | as before (was row 3) |

Without the file: four plaques, row 2 is **Load Game** (the slot list; EU: the
port's lettering in the five languages since 2026-10-28, US: the game's own),
Quit game is row 3. `dw3.log` says which at the title: `dw3-title-menu: no
autosave.bin: plaques New Game, Options, Load Game (slot list), Quit game` or
`dw3-title-menu: plaques New Game, Options, Continue (autosave.bin), Load Game
(slot list), Quit game`.

**Why a title entry (preferred option a) and not the load screen (b):** the
title already has port-drawn plaques (patch 0123, `nx_title_overlay` /
`title_menu_overlay`); a row is a small change to one menu task. The load screen
(STGMCARD) lists exactly the three slots of one card with a fixed layout and a
card/port picker; an extra entry there means new windows, cursor logic and
layout in the decomp for every language. The owner then chose Continue as the
entry, which is the title row.

**How Continue loads (patch 0142):** `STDWTITL_leaveTitle` choice 4 does what
a Continue does after the load screen's last step: `newGame()`, clear gauges,
`setFileName()`, then `GAME_SAVE` is replaced by the saved bytes (the file is
checked again: DW3 info section, slot checksum, this build's version byte;
`dw3_autosave_load`), the `.cheats` mark of `autosave.cheats` is read
(`dw3_cheats_save_loaded`), the auto-save baseline is reset, and
`requestMode(GAME.fieldMode)` enters the saved field. The only things skipped
are the load screen's own windows and panels (and its music). If the file turns
out unreadable it falls back to the slot list (`MODE_CONTINUE`). **A load of
this kind is a Continue of a normal slot in every way the game can see**, except
that the previous mode is the title rather than the load screen.

Layout: the five plaques are 40 px high on a 44 px pitch (the four are 48 on
52), every row on the same pitch, Quit game too (it was set apart by 8-10
px until the owner's preview.38 OLED note on uneven spacing); the last bottom
edge is 588 (four) / 600 (five), above the credits. The
lettering of **Continue** is new in all five EU languages (English on US):
Continue / Continuer / Weiter / Continuar / Continua
(`tools/generate_pc_title_lettering.py`). The overlay atlas has seven states
now (PRESS START, five rows, Options) on PC and Switch. The owner's OLED
reports about uneven title spacing and the logo shrinking were fixed after
this (`fix/title-spacing-logo`, patch `0129`).

## When it saves

The hook sits in `openFieldMenu` (patch 0140, unchanged): the first idle frame
of a field map that is not the one seen before; no event, menu, inn, talk,
climb, banner or fade, no battle starting; **`progress` of 4 or more**; a map in
the save list's table (`STGMCARD_prevModes`, 239 modes). Not after a battle, not
on a timer. The first idle frame after a load or a new game is only noted (the
baseline). There is no target any more: it no longer needs "a slot used in this
run", so a new game saves at its first area change after progress 4.

**Only on an area change.** Nothing else calls `dw3_autosave_commit`: there is no
write on HOME, on sleep, on Close Software or at exit (checked 2026-10-28:
`dw3_autosave_commit` has one caller, the field hook in patch 0140). The focus-loss
and exit paths (`memcard_host_flush_settled`, `memcard_host_shutdown`) flush only
RAM images that are already dirty; a commit flushes at once, so there is nothing
left dirty for them to write (P5.3). The owner's preview.41 note said the file
also changed "on HOME close"; the code does not do that, so the note is open and
needs a re-check on the OLED (item 3 of the checklist below, with the save file's
timestamp before and after HOME).

The save is made into a private copy, `GAME` is not changed, so a game with the
option on plays as with it off. The summary's place is string 43.

**Failure.** Two writes into the RAM image of the file, then one rename-atomic
flush; if the flush fails the old bytes are put back (or, for a first write, the
file is dropped) and the file on disk is the old one. Logged as
`dw3-autosave: FAILED to write autosave.bin ...`; no on-screen notice yet (open).

**Cheat marks (P6.20).** `autosave.cheats` marks `autosave.bin` as written with
cheats exactly as `save<N>.cheats` does for a slot (port 2 of the mark code); a
Continue of it keeps the game marked. Log: `dw3-cheats: autosave.bin slot 0
marked: written with cheats`, and on the load `loaded autosave.bin slot 0, which
was written with cheats`.

**Per-user saves (P6.26).** The file lives in the card folder, so it follows
whatever folder a user gets.

## Design

| Piece | Where |
|---|---|
| Policy (`dw3_autosave_decide`), idle-frame state machine, the write, the check and the load | `port/autosave/autosave.c`, `port/include/port_autosave.h` |
| Third resident file `MEMCARD_HOST_AUTO` (slot 2, `autosave.bin`; the game's `MemCard*` calls only reach ports 0 and 1) | `port/memcard/memcard_host.c` |
| Cheat mark of port 2 (`autosave.cheats`) | `port/options/cheat_saves.c`, `cheats.c` |
| Area string of a mode | `port/autosave/autosave_areas.c` |
| The Options row | `port/options/port_options.c`, overlay `platforms/pc/src/title_overlay_art.c` |
| Field hook, snapshot | patch `0140` |
| Load baseline, title start (looks at the file again) | patch `0141` |
| Continue / Load rows, choice 4 | patch `0142`, `port/include/port_title_options.h` (`dw3_port_title_load_row`), `port/options/title_entry.c`, overlay art + atlas (`STATE_COUNT` 7) |

Log lines: `dw3-autosave: autosave.bin found: Continue loads it` (title start, file
present); `area change to mode 0x..: saving to autosave.bin`; `wrote autosave.bin
(area mode 0x.., #N)`; `Continue loads autosave.bin`; `not saved ...` / `FAILED ...`.

## OLED checklist (owner, US and EU builds from this PR)

1. No auto-save file (delete `autosave.bin` or fresh card folder): the title
   looks as before, four plaques; the third opens the slot list.
2. Options: nine rows, Auto-save OFF; its message line mentions its own file and
   Continue, in the disc's language on EU.
3. Auto-save to **Each area**. Load a save, reach progress 4 or more (any saved
   game past the start), walk through a door. `dw3.log`: `area change ...`,
   `wrote autosave.bin`. On the SD card `autosave.bin` appears; `save0.bin` and
   `save1.bin` are byte-identical to before (their timestamps do not change),
   and no new `.pre-auto`.
4. Close the game, relaunch: the title has **five** plaques: New Game, Options,
   **Continue**, **Load Game**, Quit game, evenly spaced, all lettered (EU: in
   the language chosen). Continue goes into the new area at once, no card
   screen. Load Game opens the slot list with your own slots, unchanged.
5. A new game with the option on: at its first area change after progress 4 the
   old `autosave.bin` is replaced.
6. Option back to OFF, `autosave.bin` still there: Continue still loads it, and
   it is not rewritten.
7. With a cheat used before the area change: `autosave.cheats` appears and
   Continue shows the game marked (cheat saves count).
8. Not covered by the PC replays: a real SD write failure, HOME during the
   write, the cost of the write at an area change (a feel check is enough).
