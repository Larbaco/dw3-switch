# P4.5 — Filesystem + log + time (status)

**Status: closed** for the formal CDFS acceptance criterion. Switch backend
units (`nx_file` / `nx_log` / `nx_os`) were fixed earlier; this note now
records the formal P2.5 suite that targets the packed P1.6 tree on PC or SD.

## Done-when (roadmap)

Formal P2.5 CDFS suite (`tools/cdfs_suite`) passes against a packed runtime
root: map load, path reject, file-id `cdfs_read`, `cdfs_read_at`, and
`cdfs_lookup_lba`. The Switch SD tree is the same relative layout as PC
`runtime/<ver>/` under `sdmc:/switch/dw3/<ver>/` — only the mount prefix
differs (`docs/RUNTIME_LAYOUT.md`).

## Formal suite

| Piece | Role |
|---|---|
| `tools/cdfs_suite.c` | Host CLI: `--self-test WORKDIR` (mini fixture + path reject) or `--root DIR` (packed tree) |
| `tools/tests/test_cdfs_suite.py` | Always runs self-test; packed-root run when `runtime/us`, `runtime/eu`, `DW3_CDFS_ROOT`, or `DW3_SD_RUNTIME` exists |
| `tools/tests/test_cdfs.py` | Wave-1 `cdfs_cat` checks (unchanged mini fixture + optional owner spot-check) |

Checks covered by `cdfs_suite`:

1. **Map load** — default `files_us.json` / `files_eu.json` (or `--map`).
2. **Path reject** — `../` and absolute map paths fail load (self-test).
3. **File-id reads** — `cdfs_read` byte-identical to host files (samples).
4. **Partial reads** — `cdfs_read_at` windows + EOF zero-fill.
5. **LBA lookup** — `cdfs_lookup_lba` for sample base (and interior) LBAs.
6. **Multi-sector** — at least one `sectors >= 2` entry (full read if under
   `--max-full`, else window + LBA).
7. **Unknown id** — `cdfs_read` fails.

### Host evidence (this workstream)

```bash
# From a checkout with owner runtime/us (gitignored; never invent assets):
gcc -std=c11 -Wall -Wextra -Werror -O2 \
  -o build/cdfs_suite tools/cdfs_suite.c port/cdfs/cdfs.c -Iport/cdfs
./build/cdfs_suite --self-test /tmp/cdfs-self   # 0 fail
./build/cdfs_suite --root runtime/us            # 0 fail (map + samples + LBA)

python3 -m pytest tools/tests/test_cdfs_suite.py tools/tests/test_cdfs.py -v
# self-test + packed runtime/us + Wave-1 mini: all passed
```

## OLED / SD validation (owner)

The suite is host code over stdio. It does **not** need a special `.nro`. To
exercise the **same bytes** that the OLED reads from `sdmc:`:

1. Pack or copy the US tree so it matches P1.6 (`files_us.json`, `SLUS_014.36`,
   `AAA/…`, `memcard/`). See `docs/DISC_SETUP.md` / `docs/RUNTIME_LAYOUT.md`.
2. On the SD card the game uses: `sdmc:/switch/dw3/us/` (same relative layout).
3. Either:
   - **A (preferred):** mount the SD on Linux (or FTP/copy the `us/` tree to
     the PC) and run:
     ```bash
     gcc -std=c11 -Wall -Wextra -O2 \
       -o build/cdfs_suite tools/cdfs_suite.c port/cdfs/cdfs.c -Iport/cdfs
     ./build/cdfs_suite --root /path/to/switch/dw3/us
     # or:
     DW3_SD_RUNTIME=/path/to/switch/dw3/us python3 -m pytest \
       tools/tests/test_cdfs_suite.py -k packed -v
     ```
   - **B:** keep using PC `runtime/us` that you sync to the card; the suite
     against that tree is the formal packed-runtime acceptance. Preview.4
     already proved libnx `sdmc:` open/read for the same layout
     (`cdfs` root `sdmc:/switch/dw3/us`, map load, boot TIM, STR rewrite).

Retain the suite stdout (or pytest log). Do not treat title/movie smoke alone
as the CDFS suite — the suite output above is the record.
