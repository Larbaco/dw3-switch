# P4.5 — Filesystem + log + time (status)

Scope this session: audit and fix concrete gaps in the Switch backend units
`nx_file.c`, `nx_log.c`, `nx_os.c`, `nx_gpu.c`, and trace the P1.6 runtime
layout through the `port/cdfs` read path. Switch-specific code only; no shared
`docs/ROADMAP.md` / inventory edits.

**P4.5 done-when (roadmap): P2.5's cdfs tests pass on hardware against the SD
layout. Partially exercised on the OLED by preview.4; the formal P2.5 hardware
suite was not run, so P4.5 remains unchecked.** This note records what did land
and the exact blocker.

## What changed

| File | Defect | Fix |
|---|---|---|
| `platforms/switch/psyz_backend/nx_file.c` | `dw3_nx_fs_mount_sd()` returned false whenever `fsdevMountSdmc()` failed. That is what an *already-mounted* `sdmc:` produces (hbmenu, another homebrew, a re-entry), so boot logged a false "runtime paths will not resolve" even though paths resolved. | A failed mount is only fatal when `fsdevGetDeviceFileSystem("sdmc")` is also NULL — the devoptab is the source of truth, not the Result. Also fixed a stale comment that pointed at `source/main.c`; `DW3_DEFAULT_RUNTIME` lives in `source/boot_main.c` (verified by grep). |
| `platforms/switch/psyz_backend/nx_os.c` | `Psyz_OsThreadStart()` `free()`'d the `Thread` object when `threadStart()` failed, but `threadCreate()` had already succeeded, so `*t` was a live libnx handle — a use-after-free. | The failure path now `threadClose(t)` before `free(t)`, releasing the handle first (libnx `thread.h`: "Frees up resources associated with a thread"). |

Audited, no concrete defect found, left unchanged:

- `nx_log.c` — three sinks (stderr / `sdmc:.../dw3.log` / `svcOutputDebugString`)
  with `fflush` after each write; the `snprintf` truncation clamp is correct.
  Logging is not mutex-guarded, but neither PSY-Z's PSP nor SDL backend is, so
  that is not treated as a P4.5 defect here.
- `nx_gpu.c` — `Psyz_VideoVSync` mirrors the PSP/SDL shape (64 µs/scanline,
  32-bit µs subtraction); the one-shot boot-trace lines are diagnostic and were
  left in place, not removed.
- `nx_os.c` bell/`OsNowUs` boot-hang instrumentation left in place (still useful
  for the next boot stop; the original reason — the recursive audio lock — is
  fixed but the trace is cheap and one-shot/bounded).

## P1.6 layout → cdfs read path (trace)

- `docs/RUNTIME_LAYOUT.md`: PC `runtime/<ver>/`, Switch `sdmc:/switch/dw3/<ver>/`,
  with `files_<ver>.json`, `SLUS_014.36`/`SLES_039.36`, `boot_tim.bin`, `AAA/…`.
- `nx_file.c` creates only the parent `sdmc:/switch/dw3`; the version tree is
  owner-supplied (no assets are vendored or invented — AGENTS.md directive 5).
- `source/boot_main.c`: `cdfs_set_root(DW3_DEFAULT_RUNTIME)` →
  `cdfs_load_map(NULL)` → `join_path` reads via stdio `fopen` under the root.
- `port/cdfs/cdfs.c`: `cdfs_load_map` defaults to `<root>/files_us.json` then
  `files_eu.json`; `path_is_safe_relative` rejects absolute / `..` escapes;
  `cdfs_read`/`cdfs_read_at`/`cdfs_lookup_lba` read packed host files directly.
  All platform-independent, so the SD path is the *same* code exercised by the
  host tests — the only unverified link is libnx `sdmc:` I/O itself, which needs
  hardware.

## OLED preview.4 evidence (2026-10-11)

The owner ran the preview.4 game NRO on the OLED using nxlink. The runtime
root and CDFS map loaded from `sdmc:/switch/dw3/us`; the boot TIM, audio,
memcards, and 13 raw STR rewrites were read/written successfully. This proves
real SD-backed runtime and disc-sector access in this run. The owner later
removed `us/` and observed that the game no longer booted. That image only
rewrote STR files from the BIN.

US boot now extracts the rest of the runtime from the same Mode2/2352 BIN
when `us/` is missing (`port/cdfs/runtime_extract.c`, called from
`boot_main.c` and the PC host before `cdfs_load_map`). Form-1 files are the
2048-byte user payload. Form-2 `.STR` files are raw `sectors * 2352`.
`boot_tim.bin` comes from the PS-X EXE tail. `memcard/` is created empty and
existing `.mcr` files are left in place. A second boot only stats a complete
tree. EU is unchanged.

This extract was checked with a synthetic Mode2 image
(`tools/tests/test_runtime_extract.py`). It has not been run on the OLED.
This was **not** the formal P2.5 CDFS hardware test suite; no exhaustive
`cdfs_read`/`cdfs_read_at`/`cdfs_lookup_lba` suite was run on the console, so
P4.5's done-when remains open.
