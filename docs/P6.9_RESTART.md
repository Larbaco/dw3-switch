# P6.9 in-process game restart

Controls, physical mappings, and diagnostic chord overlap: [HOTKEYS.md](HOTKEYS.md).

The title Port options shell exposes **Restart hotkey**, OFF by default. It is
saved with the other Port options since P9.4 (`port_options.cfg`, see
[PORT_OPTIONS.md](PORT_OPTIONS.md#persistence)), so enabling it once keeps it
across launches. Enable it from the title shell, then hold the PS1 logical buttons **L1 + R1 + Start + Select**.
On PC's keyboard map this is Q + R + Enter + Backspace. Switch uses the same
logical pad buttons.

`port/options/restart.c` owns the chord, opt-in check, and P5.3
`memcard_host_flush_all()` call. A flush error cancels the restart and leaves
the current game running. A successful flush asks the existing game loop to
reset its in-memory `GAME` state, discard the active mode task, hide the
native title overlay, and continue through the same `dw3_game_main()` call. It does
not repeat PSY-Z, CD, audio, heap, pad, or graphics initialization, and it
does not format or edit save data.

## Boot target after restart

Restart re-runs `newGame()`, so it lands where a cold host boot lands. US goes
to the title. EU goes to the language selection (`CNTY_SEL`) with `LANGUAGE`
cleared, and the player chooses a language again. This matches a real PS1
reset (which returns to the country select) and means a language change needs
no host relaunch. It is not "skip to title with the old language".

The native title overlay (Switch GLES / PC SDL3 GPU: menu plaques, logo
texture, edge-fade level) is only hidden by title-task draws, and the title
task is discarded on restart. Before the fix, an EU restart from the title left
the overlay's active flags set while the mode became `CNTY_SEL`, so the title
menu and logo drew on top of the language screen (owner report, preview.26).
`dw3_port_title_overlay_reset()` now clears the overlay state as part of the
restart.

## Validation

On 2026-10-13, the PC game was run on a private Xvfb display using the owner's
existing runtime as read-only input and an empty memcard directory under
`/dev/shm`. The title shell enabled the setting; the chord produced
`saves flushed; returning to title in-process`, followed by the title mode
entry again. Host startup and `dw3_game_main()` entry did not repeat. The
options state-machine test confirms OFF by default and that the setting can
be enabled. The PC `dw3-pc` target linked successfully.

P6.9 remains open until the Switch build and hardware chord are validated and
a save written before restart is shown to load with Continue afterwards.
The opt-in setting is persisted by P9.4. A restart does not re-read the
option file: the registry is host-owned and stays as it is in RAM, which
already equals the file because every change is written when it is made.

### 2026-10-15, Ryubing (Xvfb, keyboard as Player 1)

Before the fix (main at `8d62d55`), EU: choose Deutsch, reach the title, enable
Restart hotkey, chord: title plaques and logo drawn over SELECT LANGUAGE
(reproduced). After the fix: EU restart from the title and from the field
(new game, first dialogue) shows a clean language selection; a second language
choice (Francais) applies to the title, and a second restart works. US restart
from the title and from an opening movie returns to PRESS START with no
leftover overlay. Not automated: restart after a battle, after a save written
by the game, and US restart in the field (the opening movie could not be
skipped by the input script).

**PC implementation / evidence (2026-10-13):** title Port options has an
opt-in restart setting (OFF by default; saved since P9.4). The PS1 logical
chord L1+R1+Start+Select runs shared `port/` policy, flushes P5.3 dirty
saves, and cancels if flushing fails. It resets `GAME` state and the active
mode/overlay inside the existing `dw3_game_main()` loop; host, PSY-Z, audio,
heap, pad, and graphics initialization do not run again. Private Xvfb PC run
returned to title after the successful flush. See
[P6.9_RESTART.md](P6.9_RESTART.md).
**Owner OLED feedback (2026-10-14, EU preview.26):** the restart hotkey
works. However, choosing a language, reaching the main menu, then restarting
leaves the title menu above the language-selection screen. Cause: the
native title overlay state was only cleared by title-task draws, which a
restart discards; EU re-enters `CNTY_SEL`, so the overlay (menu plaques,
logo, fade) stayed up. Fix: restart now resets that overlay and, as on a
real PS1 reset, EU returns to a clean language selection. Ryubing US and EU
validation in [P6.9_RESTART.md](P6.9_RESTART.md). Continue reload of a save
written before restart is not newly confirmed; P6.9 stays open.
**Status (2026-10-15):** the EU restart overlay bug is fixed in #162
(Ryubing US and EU). Still open: restart before/after a battle and after
an in-game save on both discs, and an OLED retest.
