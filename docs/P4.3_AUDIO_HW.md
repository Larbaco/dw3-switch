# P4.3 Audio hardware — underrun measurement & hardware-listen plan

Status: **plan (2026-10-16)**. The measurement does not exist on hardware yet;
P4.3 in `docs/ROADMAP.md` stays open. Companion to [P4.3_AUDIO.md](P4.3_AUDIO.md).

> The audren output thread has driven the game image since P4.3 backend work
> landed (Ryubing XA listen at preview.21; owner "sounding perfect" checks
> earlier). What the done-when still needs is (a) one hardware session and
> (b) an underrun number from that session. The counter in `nx_audio.c`
> cannot see the actual starved pass today, and the session has no
> audren-side progress evidence in its log. This note fixes both: a
> countable underrun definition, the audren-native counters to export, and
> the session recipe.

## Where the instrument lives today

| Piece | Location |
|---|---|
| audren thread, 4 × 1024-frame wavebufs (~23 ms each, ~92 ms queue) | `platforms/switch/psyz_backend/nx_audio.c` |
| `s_underruns` counter — two rules | same (`audio_thread`) |
| Stats surface (`Dw3NxAudioStats`) | `platforms/switch/psyz_backend/nx.h` |
| 1 Hz stderr line (`audio queued=… underruns=…`) | `platforms/switch/source/main.c` (Makefile sample) |
| Game drop-in log lines (`frame dt us=`, `mem dbg:`) | `platforms/switch/source/boot_main.c`, `psyz_backend/nx_mem_budget.c` |

Config as linked: renderer bus 48 kHz (`AUDREN_SAMPLES_PER_FRAME_48KHZ` = 240),
voice at 44.1 kHz, 24 voices (1 used), 1 device sink, 2 mix buffers,
5 ms update cadence (`audrenWaitFrame` on the `QuerySystemEvent`).

## Why the current counter is not a measurement

`audio_thread` increments `s_underruns` in two places, neither of which
reliably observes an underrun in steady state:

- **Add-failure** (`audrvVoiceAddWaveBuf` returns false): the refill loop
  only calls it for wavebufs already in `Free`/`Done` state, and libnx
  rejects only misaligned pointers there. Practically unreachable — it is
  a self-check, not an underrun signal.
- **Dead-voice** (`!audrvVoiceIsPlaying && queued_this_pass == 0`): the
  check runs *after* the refill loop. An underruned pass starves while
  `audrvUpdate` pulls empty, but the pass also re-queues buffers, so
  `first_wavebuf` is non-NULL again by the time the check runs. It only
  fires if a refill produced nothing.
- libnx never reads the voice play-state back from the update response
  (`nx/source/audio/voice.c: _audrvVoiceUpdate` only copies wavebuf
  progress), so "running dry" never flips a state bit we could read.

So on hardware the number stays ~0 without proving silence-free playback.

## libnx audren signals available (verified against libnx)

| API | Meaning | Refresh |
|---|---|---|
| `audrvVoiceGetPlayedSampleCount(&drv, 0)` (u32) | samples the ADSP consumed for the voice | every `audrvUpdate` (`AudioRendererVoiceInfoOut.played_sample_count`) |
| `audrvVoiceGetWaveBufSeq(&drv, 0)` (u32) | cumulative wavebufs released to `Done` | every `audrvUpdate` (`num_wavebufs_consumed`) |
| `audrvVoiceGetVoiceDropsCount(&drv, 0)` (u32) | audren's own drop counter for the voice | every `audrvUpdate` (`voice_drops_count`) |
| `audrenWaitFrame()` | waits the renderer service event (200 Hz timer, autoclear) | per pass |

Mechanics as verified in libnx (`nx/source/audio/voice.c`,
`nx/source/services/audren.c`): the wavebuf lifecycle is
`Free/Waiting → Queued → Playing → Done`; "Done" transitions come from the
ADSP response, not from a separate event we can register
(`RegisterBufferEvent` belongs to the `audout` service, which is not the
path this port uses); `audrenWaitFrame` waits the service-owned frame
event directly. No revision knob: libnx caps the behavior revision at
`AUDREN_REVISION_4` for
4.0.0+ systems (`nx/source/services/audren.c`, the REV5/REV6 branches are
commented out upstream); header/revision tuning is not our lever. The only
real knob is buffer sizing.

## The counting rule to implement

In `nx_audio.c` `audio_thread`, **before** the refill loop:

```c
/* Starved pass: every wavebuf is back (Free/Done) while we are unpaused,
 * audren ticks and we are not intentionally silent. The ADSP consumed one
 * buffer per ~23 ms, so all-4-free at a 5 ms pass boundary means the queue
 * emptied: one count per dry pass; a long starvation window accumulates. */
```

Rule (per pass, at pass top):

1. Count wavebufs with `state == Free || state == Done`.
2. If that count == `NUM_BUFFERS`, `!s_paused`, `!s_stop`, and at least one
   `audrvUpdate` has happened since init → `s_underruns++`.

Keep the two existing increments (they fire only in genuinely-degraded
states) and the `buffers_queued` stat. Suppress counting while paused and
during the first prime (guard with a per-init pass counter).

## Stats + log surface to add

- Extend `Dw3NxAudioStats` with `wavebufs_consumed`, `played_samples`,
  `voice_drops` (u32 values read after `audrvUpdate`; unsynchronized reads
  of fresh u32s are acceptable for a trend line, document that).
- On hardware, extend the 1 Hz line: the Makefile sample already prints the
  audio fields; the game image should get the same fields in its
  `frame dt us=` / `mem dbg:` area (`nx_audio dbg: underruns=N seq=M
  played=K drops=D`), plus the HUD audio stats. `seq` must advance while
  unpaused — evidence that audren pulls at all; `played ≈ 44100×t` is the
  consumption clock.
- The done-when number the owner has to approve: suggested wording is
  "0 underruns over a ≥10 min nxlink session covering movie XA, field BGM
  and battle SFX" — bump `BUF_FRAMES` 1024 → 2048 (~46 ms per buffer,
  ~184 ms queue; latency does not matter for PS1 audio) and rerun once if
  dry passes appear while sound breaks.

## Hardware session recipe

1. Build the game `.nro` (`tools/build_switch_game.sh --nxlink` or Docker
   `DW3_DK_TMPBUILD`; see [P4.3_AUDIO.md](P4.3_AUDIO.md)).
2. `nxlink -s` (hbmenu **Y** NetLoader; do not probe 28280 first) and keep
   the stderr tail open.
3. Session ≥10 min: title 1 min → opening movie (XA) 2 min → field walk 4 min
   → battle 3 min (fighters + menus) → one memcard save/stop window.
4. Capture: `Psyz_AudioInit OK` line up top, `nx_audio dbg:` lines
   thereafter, `underruns=0`, and no `audrvUpdate failed` lines. Save the log
   under `tmp/evidence` (dates + session note; do not commit it).
5. Listen check on the same session (heads as agreed in the roadmap note):
   movie XA mix, field BGM, battle SFX, no gap under load.
6. Then tick P4.3 in `docs/ROADMAP.md` with the session date and log path —
   the plan belongs in [P4.3_AUDIO.md](P4.3_AUDIO.md) history lists.
