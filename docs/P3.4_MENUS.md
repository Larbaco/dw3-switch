## Evidence (2026-10-10) — STGMCARD save → `.mcr`

Root cause of the earlier “write pending forever” hang: on LP64,
`MEMCARD` and `MEMCARD_FUNCS` were separate globals with a 0x20 align gap, so
`MEMCARD_SYSTEM.funcs.write` called `setHeader` and left `status==0`.
Patch `0028` bundles them in `g_dw3_memcard`.

```
dw3: MemCardCreate auto file=BASLUS-01436DMW3-USA blocks=4 frame=1
dw3: _card_write ok chan=0 block=68 slot=0 (.mcr)
… (sector writes through info + GameSave) …
dw3: STGMCARD_writeSave port=0 slot=0 status=1
dw3: STGMCARD force-save done, leaving
```

| | SHA-256 of `memcard0.mcr` |
|---|---|
| Fresh formatted | `7706c7d43edaf8cb7618e574f03457105153e3bdc196db803a600ad96a8f58e8` |
| After force-save | `ac323876acf143a0335d5675fa7a65e7a313d0f669d9d708e0680502c0fa9d20` |

Diff vs fresh: **10240** bytes. Logs:
`/tmp/dw3-p34-evidence/final-mcard-save-ok.stderr`.

`MemCardReadFile` is implemented on the same path (load e2e not separately
forced yet).

## Evidence (2026-10-10) — pad START → MODE_STATUS

LE host previously stored auto-pad masks in PS1 wire MSB-first order, so
`PadData.buttons` (native `u16`) never saw Start/Cross. Fix: store the
active-low mask in native byte order in `psyz_pad_host.c`.
