# P3.4 — Menus and shops (PC)

## Status (2026-10-10)

**Partial.** All listed menu overlays are linked into `dw3-pc` and open from
field via `FIELDSTG_leaveField` (`DW3_FORCE_MENU`). Open → return to
`FIELDSTG` (`0x2d7`) is proven for `STSTATUS`, `STITSHOP`, `STGTRAIN`,
`STGDGLAB`, `STDGNAME`, and `STGMCARD` (load/save screen entry). `STPLNMET`
was already Done-when for P3.2.

**STGMCARD save (P2.7) proven:** force-save completes
`MEMCARD_SYSTEM.write` → `MemCardWriteFile` → `_card_write` →
`memcard0.mcr` mutation (see Evidence below).

**Pad START→status (partial):** with LE host pad byte-order fix in
`psyz_pad_host.c`, `DW3_FORCE_FIELD_MENU` + `DW3_AUTO_PAD=start,confirm`
reaches field START menu then `MODE_STATUS` (`0x1000`) / `STSTATUS`
restore. Triangle return and pure pad-only START (no FORCE_FIELD_MENU)
still open.

**NPC script entry (partial):** patch `0031` + `cdfs_read_at` —
`DW3_FORCE_NPC_ACTION` calls `FLAGS_00.applyAction` and
`leaveField` into shop/gym/lab (`0xF00` / `0xA00` / `0xD00`) with
`AUTO_MENU_RETURN` back to field. Still host-forced, not walking up to
an NPC.

**Not Done-when:** pure pad START→status→Triangle return, real NPC
proximity/talk, naming via script, STGMCARD load e2e. Checkbox stays
open until those land.

## Evidence (2026-10-10) — STGMCARD save → `.mcr`

Root cause of the earlier “write pending forever” hang: on LP64,
`MEMCARD` and `MEMCARD_FUNCS` were separate globals with a 0x20 align gap, so
`MEMCARD_SYSTEM.funcs.write` called `setHeader` and left `status==0`.
Patch `0028` bundles them in `g_dw3_memcard`.

```
dw3: MemCardCreate auto file=BASLUS-01436DMW3-USA blocks=4 frame=1
dw3: _card_write ok chan=0 block=68 slot=0 (.mcr)
… (sector writes through info + GameSave) …
dw3: STGMCARD_writeSave port=0 slot=0 status=1
dw3: STGMCARD force-save done, leaving
```

| | SHA-256 of `memcard0.mcr` |
|---|---|
| Fresh formatted | `7706c7d43edaf8cb7618e574f03457105153e3bdc196db803a600ad96a8f58e8` |
| After force-save | `ac323876acf143a0335d5675fa7a65e7a313d0f669d9d708e0680502c0fa9d20` |

Diff vs fresh: **10240** bytes. Logs:
`/tmp/dw3-p34-evidence/final-mcard-save-ok.stderr`.

`MemCardReadFile` is implemented on the same path (load e2e not separately
forced yet).

## Evidence (2026-10-10) — pad START → MODE_STATUS

LE host previously stored auto-pad masks in PS1 wire MSB-first order, so
`PadData.buttons` (native `u16`) never saw Start/Cross. Fix: store the
active-low mask in native byte order in `psyz_pad_host.c`.

```bash
DW3_START_MODE=0x2D7 DW3_PROGRESS=4 DW3_FORCE_FIELD_MENU=1 \
  DW3_AUTO_PAD=start,confirm,cancel SDL_VIDEODRIVER=dummy \
  ./build/pc/dw3-pc --runtime runtime/us
```

```
dw3-pad: buttons pressed mask=0x0040 (raw bytes ff bf)
dw3: DW3_FORCE_FIELD_MENU open START menu
dw3: field menu -> MODE_STATUS option=0
dw3: overlay restore file=0x1f9 …
dw3: mode=0x1000 …
```

Filtered log: `/tmp/dw3-p34-evidence/field-menu-start-status.stderr`.
