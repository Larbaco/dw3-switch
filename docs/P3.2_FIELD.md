## Boot path (title → new game → name → field)

1. **Title:** default `MODE_TITLE` (`0xE00`) — `STDWTITL` (P2.8).
2. **New game (menu):** `title.c` → `GAME.funcs.requestMode(MODE_NEW_GAME, 0)`
   (`0x2D7`) → `FIELDSTG` + `FIELDSTG_pickStage` → **WSTAG780**.
3. **Intro door (script):** progress `0` starts event `0` (`script0`); ends
   with `SCRIPT_LEAVE(0x2D8, …)` → **WSTAG785** via `FIELDSTG_leaveField`.
4. **Name entry:** Online Center event `1` → `SCRIPT_LEAVE(0x500, …)` →
   `STPLNMET`; on exit `requestMode(0x2D8, 0)` → **WSTAG785** again.
5. **Chamber Room:** progress `1` event on 785 → `SCRIPT_LEAVE(0x2D9, …)` →
   **WSTAG790** (file 476). FAST path continues into further leaves (e.g.
   `0xE02` movie/title) once 790's intro scripts run.

WSTAG780/785 have **no** `stageSlots`; physical `SLOT_EXIT` triggers are
not used on these maps. The first-stage “door” is the intro
`SCRIPT_LEAVE`.

## Host field-tile pace

On a PS1, `FIELDSTG_requestTiles` starts one `CD_READER.read` and then
stops, because `CD_READER.isBusy()` stays true until the drive finishes.
The host path completes `fread` inside that call and used to return
idle, so the same call issued every visible tile (up to about 30) before
the frame was presented. Walking and map entry hitch. Standing still
on a warm cache does not.

`cdfs_read_field_tile` (`port/cdfs`) still copies the tile immediately,
then reports busy until `cdfs_poll`. The decomp loop is unchanged.
Patch `0041` calls `cdfs_poll` from `vsyncCallback` once per VSync, the
frame boundary on PC and Switch, and `isCdReading` observes the hold.
A synchronous `FILE_CACHE.load` also calls `cdfs_poll`: the tile bytes
are already in the stream buffer, and the hold only paces the next tile,
so that load must not spin until the next vblank. One large tile can
still run past a single vblank inside its `fread`.
