## 1. Where the game draws the PS button icons (proved)

**They are font icons, not sprites.** `loadFont()` (`src/engine/text/font.c:4-9`)
loads `FILE_FONT` (US 0x278 = `AAA/DAT/COMMON/CMFONTTM.BIN`, EU 0x287 =
`AAA/DAT/COUNTRY/CMFONTTM.BIN`) with `TimLoader.loadArchive`
(`src/engine/gfx/tim_loader.c`), which puts each archive entry in VRAM 0x40
halfwords apart from x = 0x140. Called from `src/engine/system/main.c:66` and
`src/menus/title/movie.c:263` only, so there are two hook points.

- The archive has **two** entries, each a raw 64x256 halfword block (a 16-bit TIM
  used as storage). The game reads them as **4 bpp**, so a font page is 256x256
  texels, low nibble first. A glyph's `page` (0 or 1) is added as `page << 6`
  to the tpage x (`text_window.c:228`).
- `TextStyle` (`include/engine/text.h`, table `FONT_STYLES` in `font.c:66`) has
  three sizes (line 14, 11, 9 px) and per size a `Glyph icons[114]`
  (`FONT_ICONS_1/2/3`, `src/engine/text/text_tools.c:431, 671, 911`, with
  `#if VERSION_US` / `VERSION_EU` branches). `Glyph` = `{page, u, v, clutX,
  clutY, w, h, dx, dy, advance, _}`.
- An icon is reached in two ways (`decodeChar`, `font.c:20`): the bytes `01 n`
  in a string, or a Shift-JIS code looked up in `FONT_ICON_MAP`
  (`text_tools.c:244`). The drawn cell is `icons[n - 1]`
  (`processTextChar` case 1, `text_window.c:~600`). Map position n is the table
  index plus one, so 0x81A2 is n = 52 and `FONT_ICONS_k[51]`.
- A cell with `page == 0xFF` is skipped, nothing is drawn (`text_window.c:219`).

**The four candidate cells, from the dump** (`tools/dump_font_cells.py`, size 1,
the only size with these icons):

| SJIS | n | US cell (page, u, v, w x h, advance) | EU cell | Art |
|---|---|---|---|---|
| 0x817E | 27 | p1 232,9, **8x12**, adv 7 | p1 232,9, **12x12**, adv 11 | US: a plain thin `x` (a multiplication sign). EU: a round pad button with an X |
| 0x819B | 47 | p0 96,72, 12x12, adv 10 | p0 96,72, 12x12, adv 11 | US: an open circle. EU: round button with a ring |
| 0x81A0 | 50 | p0 132,74, 12x12, adv 10 | p0 132,72, 12x12, adv 11 | US: an open square. EU: round button with a square |
| 0x81A2 | 52 | p0 180,74, 12x12, adv 11 | p0 180,74, 12x12, adv 11 | US: an open triangle. EU: round button with a triangle |

So **EU draws real pad-button discs and US draws plain symbols**, which matches
the owner's remark that the EU icons look nicer. The two discs do not share
cells or art; one code path must read the cell geometry from the table
(`FONT_ICONS_1`) at run time, as the bundle already says.

Facts that matter for the art:

- **Only size 1 has them.** In sizes 2 and 3 these four icons are `page 0xFF`
  (size 2 has 68 of 114 icons, size 3 only 4), so the game draws nothing for a
  button icon in 11 px and 9 px text. Three cell sizes are therefore not needed
  for the buttons; one 12x12 cell (and the 8x12 US cross) is.
- **There are no L1, R1, L2, R2, Start or Select icons in the font.** Of the 114
  icons the dump shows arrows, hearts, element symbols, a note and the four
  button shapes. If the game shows shoulder buttons it does it in words (see 2)
  or in non-font art (open question 2).
- **Palette.** `clutX = 48`, `clutY` 232 (US) or 224 (EU), plus the window's
  `palette` number as a row offset (`text_window.c:224`, `textWindowSetPalette`):
  16 colours in page 0, halfwords 48..63 of the row, 0x0000 transparent.
  - US cells use indices **1, 2 and 15** only. Rows 232 and up are the text
    colour ramps (white, greys, tints), so the US icon takes the colour of the
    text around it; the art is 3-level.
  - EU cells use indices **1..13** of rows 224..231, which are eight identical
    copies of one 13-colour palette (dark greys, red, blue, green, pink); the
    icons keep their own colours whatever the text colour.
- **Cell origin.** Every `u` of the four cells is a multiple of 4 and `w` is 8 or
  12, so a cell is a whole number of VRAM halfwords (2 or 3 per row): a
  `LoadImage` of 12 rows can replace it without read-modify-write.
- **The US cross is not a button.** In US, n = 27 is the Shift-JIS multiplication
  sign `x`, 8 px wide, probably also used in quantity text. Replacing it by a
  12 px glyph would change string widths and break "x3" style text if that is
  how it is used. EU draws the same code n = 27 as a disc. Whether the EU game
  uses it as a button, a multiplication sign or both is not proved (open
  question 2).

**Not in the decomp.** The strings are on the disc (`01 n` pairs), and the
decomp holds only one (`src/debug/vibration_test/vibration_test.c:14`, a debug
screen). A static byte scan for `01 n` was tried and is useless (the stage packs
contain the pair thousands of times by chance), so a **string census** needs
the engine's own decoding: see the step 1 hook below.

### The dev tool

`tools/dump_font_cells.py` (stdlib only, reuses `tools/extract_textures.py`):

```
python3 tools/dump_font_cells.py                       # both regions -> tmp/evidence/font_cells/{us,eu}/
python3 tools/dump_font_cells.py --version eu --ascii buttons   # ASCII art of the four cells, no files
python3 tools/dump_font_cells.py --ascii 81A2 --no-files
```

It reads `~/.cache/dw3-switch/runtime/<us|eu>/AAA/DAT/.../CMFONTTM.BIN`, parses
the `Glyph` tables for the chosen version from the decomp source, and writes per
region `page0.png`, `page1.png`, `icons_size1..3.png` (114 cells, 4x, on a grid:
n - 1 = row * 19 + column) and `manifest.csv` (size, n, SJIS, cell). It refuses
an output folder that git does not ignore. The output is the owner's game art:
never commit it. No game run was needed.

## 3. Plan for the glyph art

Owner default: **as files, Switch only, off by default** (`switch_glyphs=0|1`,
a row in the Controls group; 0 = the original icons).

**What to draw** (original, 1-bit-ish role art): `A B X Y` (face buttons, the
ones the four icons can become), plus `L R ZL ZR` for a custom map that puts the
Cross on a shoulder or trigger. `+` and `-` are not needed (no font icon for
them). Stick clicks (L3/R3) are not icons either.

**Size.** One cell: **12x12**, ring 11x11 with a 1 px margin, letter at most
5x7 (A, B, X, Y, L, R) or two 3x5 letters (ZL, ZR). A second **8x12** variant
(letter only, no ring) is needed only for the US cross cell, and only if the
census says it is a button (open question 2); until then US n = 27 stays as it
is. The advance stays that of the original cell (US 10 / 11, EU 11), so no
string changes width and the five EU languages are untouched.

**Palette constraints.** The patch writes indices only and never the CLUT. The
art is stored by **role**, not by index: 0 transparent, 1 outline, 2 body,
3 letter, 4 shade. The loader maps roles to the indices of the region at run
time:

- US: the icon takes the text colour, so use the same three indices the original
  uses (1, 2, 15). Roles outline / body / letter / shade must collapse to those
  three; letter and body must differ (a letter knocked out of a filled disc, or
  a letter on an open ring).
- EU: indices 1..5 of the shared palette are dark greys (0x39CE, index 3, is the
  lightest); pick one for the ring, one for the body and one for the letter, and
  keep the original disc colours out, since a Nintendo glyph is not colour
  coded. Exact indices are chosen at implementation time from the row 224
  values listed by the tool.

**Format and where it loads from.** Each glyph is a **PNG, 12x12, 8-bit
palette, four fixed role colours** (the format the mods already decode,
`port/mods/`). Files `a.png b.png x.png y.png l.png r.png zl.png zr.png`.

1. `sdmc:/switch/dw3/glyphs/` (PC: `<config dir>/glyphs/`): the owner's own
   override, same pattern as `sdmc:/switch/dw3/mods/<pack>/`.
2. **Bundled in romfs** (`romfs:/glyphs/`), built from `assets/glyphs/`: the
   default art, so the option works with no files on the SD card. Because the
   art is a few hundred bytes it could equally be C arrays in `port/` with the
   same PROVENANCE; files are the owner's choice and keep it replaceable.
3. A missing or bad file logs one line and falls back to the bundled glyph, then
   to the original icon.

**Licence.** `assets/glyphs/` is the exception to "Do not vend game assets"
(AGENTS.md, owner-approved 2026-10-27): original art with `LICENSE` (CC0
recommended) and `PROVENANCE.md` stating that the glyphs were drawn for this
project and that no Nintendo asset (Joy-Con images, system font, icons), no
game or console asset, tracing, img2img or upscaling was used. The glyphs are
plain letters in a ring, drawn pixel by pixel. They must not copy the exact
Nintendo button shapes beyond a letter in a circle; letters are drawn from a
pixel font made for the project (the existing generator uses DejaVu Sans Bold,
whose licence allows it, for the overlay B, X, Y).

**Patch approach: replace cells at load, not a draw-time remap.**

- Load time. Wrap `FONT.load` (the pointer in `FONT`, `font.c:78`; both callers go
  through it): after `loadFont()` returns (the pages are in VRAM after
  `DrawSync`), for each icon n in {47, 50, 52} (and 27 in EU), read
  `FONT_ICONS_1[n-1]` for `page, u, v, w, h`, pack the role art into 4 bpp
  bytes (low nibble first) and `LoadImage` the rect `x = 0x140 + page*64 + u/4,
  y = v, w/4 x h`. Re-run the same function when the map or the switch changes
  (it is four small uploads). No decomp edit, one code path for US and EU, and
  the original icon returns by re-running with the switch off (or re-calling
  `loadFont`).
- Draw-time remap (substituting the `Glyph*` in `processTextChar`, or an overlay
  on the icon) needs a decomp patch in a hot text path and a second texture
  area; it is only needed for button art outside the font, if the census finds
  any.
- Risks: the font area could be overwritten by another VRAM user (card game,
  movies); the log line below is checked after the title, a field, a battle and
  the card game. `LoadImage` of whole halfwords is safe only because every `u`
  is a multiple of 4; the loader must check `u % 4 == 0 && w % 4 == 0` and skip
  the cell with one log line otherwise.

Log (once per event): `dw3-glyphs: on|off, map=<layout>, patched N cells
(us|eu, n=47:A n=50:Y n=52:X n=27:B)`.

## 5. Next steps

1. **Census (step 1).** Count which icons appear and where. Cheapest: a
   diagnostic patch (env `DW3_ICON_CENSUS=1`) in the case 1 branch of
   `processTextChar` that logs once per distinct (n, text style, caller string
   pointer) with the current scene, then a short scripted walk (title, field,
   shop, battle, menu) on PC with `nice -n 10` and a virtual display. It decides
   US n = 27 and whether any button art lives outside the font. No art is
   drawn before it.
2. **Fix now** (section 4, items 1 and 2).
3. **Art PR:** `assets/glyphs/` with LICENSE and PROVENANCE.md, a 12x12 PNG
   check script.
4. **Patch PR:** the `FONT.load` wrapper, role-to-index maps per region, the
   `switch_glyphs` row (Switch only, default 0), log line, unit test of the
   packing, a replay case with the option off (bit-identical) and one with it on.
5. OLED test item C8 of the bundle, US and EU, two EU languages.
