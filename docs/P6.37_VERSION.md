# P6.37 Port version visible in game

Owner request, 2026-10-30. OLED test reports and bug reports must name the
build. Until now the version reached only hbmenu (the NACP `display_version`,
15 characters, e.g. `0.6.5-p.56`, by `tools/dw3_nro_version.py`), the boot log
(`dw3: version=`) and the crash report.

## Design

One label, everywhere:

```
dw3-switch v0.6.5-preview.57 (962462d) US
```

- **Label** (`tools/dw3_nro_version.py --format label`): a release tag build
  (`RELEASE_TAG` / `DW3_RELEASE_TAG`, or `git describe` landing exactly on a
  tag) is `v<tag> (<short sha>)`; a build past a tag keeps the describe form
  (`v0.6.5-preview.56-12-g8574e58`), a bare commit id stays as is, and `-dirty`
  is kept. It reuses the NACP script's raw version (the same
  `RELEASE_TAG` / `GITHUB_SHA` / `git describe` order), so the hbmenu version and
  the in-game label cannot disagree. The NACP string is unchanged.
- **Region tag**: `US` or `EU` (the running disc), `US+EU` in a combined image
  before the region is picked.
- **Build date**: `YYYY-MM-DD`, the commit date of a clean tree (so a rebuild of
  one commit gives one header), today for a dirty tree or a build without git;
  `SOURCE_DATE_EPOCH` wins.
- **Generated header** `dw3_version_gen.h` (`DW3_VERSION_RAW`, `_LABEL`, `_SHA`,
  `_BUILD_DATE`), written by the script with `--write-header` and only when its
  text changed. `port/version/port_version.c` (host side: the PC executable and
  the Switch image) turns it into the text; `port/version/version.cmake` wires it
  into a target.

### Where it shows (no decomp patch)

| Where | What | Switch |
|---|---|---|
| Options screens (the group list and every group, also in game) | dim footer line, centred under the button hints, baseline y 702 of the 960x720 canvas; always shown, no option | none |
| Title screen | the same line in the bottom right corner (right edge x 944), below the credits plaque (it ends at y 669) and clear of the logo and PRESS START; only while the title canvas is up | file-only key `show_version` in `port_options.cfg`: `1` (default) or `0` |
| `dw3.log` / stderr | `dw3-version: <label> <region> build=<date>` is the first line; a combined image logs it again once the region is picked | none |
| PC window title | `dw3-pc - dw3-switch v... US` | none |

The text is drawn from the help's glyph atlas (24 px body face, a dark shadow, a
dim blue-grey) into the title overlay's static layers
(`platforms/pc/src/title_overlay_art.c`), which the PC and the Switch share, so
both hosts get the same pixels. The Help sub-screen is its own layer and has no
footer.

### Replays

The title corner and the Options footer would change every commit, and so would
every reference. The runner sets `DW3_VERSION_OVERRIDE=replay`
(`tools/replay/replay_tests.py`), which replaces the label part
(`dw3-switch replay US`); the Switch replay build (`DW3_NX_REPLAY`) always shows
`replay`. The region tag stays real. Scenarios: `us/eu-title-noversion` (the
title with `show_version=0`) and `us/eu-options-noversion` (Options with
`show_version=0`: the footer stays).

## As built (2026-10-30)

- `tools/dw3_nro_version.py`: `--format label|header`, `--write-header PATH`,
  `--auto` (CI env when present, else git); tests in
  `tools/tests/test_dw3_nro_version.py`.
- `port/include/port_version.h`, `port/version/port_version.c`,
  `port/version/version.cmake`, test `tools/tests/test_port_version.py`.
- PC: `platforms/pc/CMakeLists.txt` calls `dw3_version_setup(dw3-pc)`: the header
  is written at configure time and again before every build of `dw3-pc` (a custom
  target; nothing recompiles when the text is the same). The log line and the
  window title come from `dw3_version_announce()`, run before `main()` (a
  constructor, so `platforms/pc/src/main.c` is untouched) and again when the
  options boot runs (the combined image, with its region).
- Switch: `tools/build_switch_game.sh` writes the header on the host with the
  same arguments as the NACP version (the devkitPro image needs no Python) and
  passes `-DDW3_VERSION_GEN_DIR`; `boot_main.c` calls `dw3_version_announce()`
  right after the log is open (before `dw3: version=`) and after the region pick.
  The script then checks that the label is inside the `.nro`.
- CI: the `switch-game` job and the release workflow go through
  `build_switch_game.sh` (the release sets `RELEASE_TAG`); the PC jobs configure
  with `--auto` (`GITHUB_SHA`).
- Replay areas (`tools/replay/areas.py`): `port/version/` selects the title and
  Options scenarios; the two-line version wiring in a PC CMake file counts as a
  source entry.
