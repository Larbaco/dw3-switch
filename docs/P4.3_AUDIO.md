## Bug: BGM plays only once (2026-10-23, owner OLED, US, rc7)

The owner reports that the background music plays one time and then stops,
in the field, in the inn and in battle, so it is not tied to one track or
mode. The suspected cause is the loop count of the SEQ/SEP sequences (the NRPN
loop controller; NRPN handling is listed as thin in
[P3.6_AUDIO.md](P3.6_AUDIO.md)). The fix is in a separate PR; this note only
records the report, nothing here was reproduced or changed. It also means the
underrun listen below has to be done on a build that has the fix, or with
music turned off, because a stopped BGM changes the mixer load.

**Update (2026-10-23, preview.30-rc8, owner OLED, US, no log):** the loop fix
(#209) works: the music loops in the field, the inn and battle. **New bug:**
after winning a battle the music stops (silence on the results screen and back
on the map; the exp and level-up SFX still play). A separate PR is fixing it;

**Follow-up (2026-10-23):** the silent results screen was a host bug (the win

reproduced on the PC host or in Ryubing on either disc; the field music logs

## Audio health line: underruns and the voice leak (#188, 2026-10-28)

Until now there was no underrun count in the log, and #188 (audio dies after
many techs) could only be told apart by the 30 s `dw3-audio: health` line,
which shows the output but not the voices libsnd could not allocate. One line
a minute now answers both from `dw3.log`:

```
dw3-audio: underruns N in last 60 s (total T), queue depth min/avg/max a/b.cc/d of 4,
  voices in use min/avg/max x/y.z/V of 24 (all in use in A of B samples),
  key-on K ok F failed (total KT ok, FT failed)[; WARNING voices ran out (#188 leak signature)]
dw3-audio: exit: ...same fields, run maxima and totals...      (once, at exit)
dw3-audio: WARNING SsUtKeyOn found no free voice (F failed so far, V of 24 voices in use now) ...
```

| Field | Source | Reads as |
|---|---|---|
| `underruns N ... (total T)` | `nx_audio.c`: a pass where every audren buffer has played out and none is queued (the output ran dry), plus the old `audrvVoiceAddWaveBuf` refusals | 0 is the goal; the P4.3 done-when is 0 over 10 min of field and battle |
| `queue depth min/avg/max of 4` | audio thread, once per pass: buffers queued or playing | stays 3 to 4; a min of 0 is an underrun |
| `voices in use` | game thread, every second frame: voices whose ENVX register (voice +0x0C) is not 0. libsnd frees a voice only when ENVX is 0 | min climbing run after run toward 24, with nothing playing, is the #188 leak |
| `all in use in A of B` | samples with 24 of 24 | non-zero means libsnd was out of voices at that moment |
| `key-on K ok F failed` | patch 0178: the result of `SsUtKeyOn` in `playSound` and `soundKeyOn` (-1 = no free voice) | F above 0 is a dropped sound; the first one and every 50th log the `WARNING SsUtKeyOn found no free voice` line |

Cost: 24 register reads every second frame under the audio lock and one log
line a minute, so it is on in release builds; nothing is rate-limited away
that matters (the warning is limited to the first failure and every 50th).
`DW3_AUDIO_STATS` and the 30 s `health` line are unchanged.

**PC:** the voice counts and key-on counts are the same code. The queue and
underruns are `n/a` there: the PC audio backend is SDL's, in PSY-Z, and has no
queue the port can see. **Switch:** all fields.

The pure arithmetic and the line format are in `port/audio/audio_health.c`,
tested by `tools/tests/test_audio_health.py`. The OLED proof lines are in
[OLED_TEST_PLAN](OLED_TEST_PLAN.md) item D13 (#188) and D14 (the underrun
listen). Not run on hardware yet; ROADMAP P4.3 stays open until the owner's
log shows the numbers.

## Goal

`audren` output thread fed by PSY-Z's software SPU mixer at **44.1 kHz**
(same pull contract as PC `sdl3_audio.c` / PSP `psp_audio.c`:
`Psyz_SpuPullSamples`).

## What landed

| Piece | Location |
|---|---|
| `Psyz_AudioInit` / Destroy / Lock / Pause | `platforms/switch/psyz_backend/nx_audio.c` |
| audren driver + 4×1024-frame wavebufs | same; voice @ 44100, renderer bus 48 kHz |
| Output thread | `threadCreate` + `audrenWaitFrame` refill loop |
| Weak SPU stubs | `Psyz_SpuInit` / `Psyz_SpuPullSamples` (440 Hz tone) until PSY-Z links |
| Sample | `platforms/switch/source/main.c` — combined `host_hello` (EGL + audren; stderr FPS + underrun counter) |
| Build | Makefile links `psyz_backend`; `DW3_DK_TMPBUILD` via `tools/dk.sh` |

The weak stubs are the Makefile sample only. The CMake game image links
`psyz_spu.c`, so those stubs are overridden there. Hearing the result on
hardware is still the P4.3 done-when.

## Build

```bash
# Linux/ext4 clone (preferred)
./tools/dk.sh make -C platforms/switch

# NTFS / drvfs checkout
DW3_DK_TMPBUILD=/tmp/dw3-dk-build ./tools/dk.sh make -C platforms/switch
```

Artifact: `platforms/switch/dw3-switch.nro` (also under
`/tmp/dw3-dk-build/src/platforms/switch/` when using TMPBUILD).

## Run on hardware

1. Copy `.nro` to the SD and launch from hbmenu.
2. Expect a hue-cycling EGL clear, continuous 440 Hz tone (stub), and nxlink
   stderr lines with `fps=…` and `audio queued=… underruns=…`.
3. **A** pause / **B** unpause / **+** exit.
4. Optional nxlink: stderr shows `nx_audio: Psyz_AudioInit OK …`.
5. On hardware, confirm underruns stay low during stable playback (not
   validated in CI or emulator-only sessions).

## Coordination with P4.2

P4.2 merged on `main` at `675f1cf` (PR #21). `phase4-audio` rebases onto
that EGL path: one `main.c` inits GPU then audio; Makefile links EGL/GLES
and `-lm`; `nx.h` exposes both APIs.
