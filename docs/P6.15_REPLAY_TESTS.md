# P6.15 Regression replay tests

First version. One command replays recorded pad input on the US build and the
EU build (all five languages) and diffs checkpoint screenshots against
references.

```bash
# once: build the PC host for both discs (separate trees, see docs/P3_EU_BUILD.md)
tools/replay_tests.sh --build --update   # build, run, write references
tools/replay_tests.sh                    # replay + compare; exit 1 on any diff
```

Needs `Xvfb`, ImageMagick `import`, and `python3-pil`. It starts its own Xvfb
on a free display (`-displayfd`, 1280x960) and never touches your real one.
Useful flags: `--only <scenario>`, `--refs DIR`, `--out DIR`,
`--bin-us/--bin-eu PATH`, `--runtime-us/--runtime-eu DIR`, `--scen-dir DIR`.
Relative paths are resolved from the directory where the command is started.
Unknown `--only` names, missing checkpoints, duplicate checkpoint names, and
checkpoint frames outside `1..UINT_MAX` or not strictly increasing are errors.
Defaults: binaries `build/pc/dw3-pc` and `build/pc-eu/dw3-pc` (or `--build`),
runtimes `runtime/{us,eu}` then `~/.cache/dw3-switch/runtime/{us,eu}`
(own-disc, see `docs/DISC_SETUP.md`), references
`~/.cache/dw3-switch/replay-refs`, results `tmp/replay/<timestamp>/`
(per-scenario captures, timestamped run logs, `report.txt`, diff images).
A full run is about one minute.

## Design

| Decision | Choice | Why |
|---|---|---|
| Target | PC host (`dw3-pc`, sdl3_gpu/lavapipe) under Xvfb | Fully deterministic and headless; runs in about a minute. Ryubing needs a GUI emulator, X11 keystroke injection and wall-clock waits. Not covered: see below. |
| Input layer | Host libpad adapter `port/psyz_missing/psyz_pad_host.c`, keyed by the `PadChkVsync` count (game frame) | Independent of host speed, Xvfb timing and turbo. No decomp edits. |
| Hook | `DW3_REPLAY=<rec>` replays, `DW3_REPLAY_RECORD=<rec>` records the real pad. Both unset = no behavior change | Off by default; env-only. While recording, `DW3_AUTO_PAD` is ignored so the recording stays tied to the real controller. |
| Checkpoints | `shot <frame> <name>` lines in the recording; the host writes the capture at that frame | Fixed frame numbers, named in the recording itself. |
| Capture | Per checkpoint: `<name>.ppm` (PS1 display frame from PSY-Z) and `<name>.png` (the whole Xvfb window, which includes the host title overlays) | The title logo/menu are PC GPU overlays that are not in the PSY-Z frame; the window grab sees them. The game thread is blocked in the hook while `import` runs, so the last presented frame is stable. |
| Compare | Per-channel tolerance 8/255; fail above 0.1% differing pixels (~1230 px of 1280x960); diff image = ref / capture / red mask | Two runs on this machine are byte-identical (0 px). The slack is for another Mesa/GPU driver, which moves some edge pixels by a few levels. One changed menu label is about 5000 px, so a real change stays well above the threshold. The cost: a single flipped pixel passes. |
| References | `~/.cache/dw3-switch/replay-refs`, outside git, generated with `--update` | They are captures of copyrighted output. `--update` rejects a reference directory inside the repository. Never commit references. Only `.rec` pad logs and scripts are committed. |
| State | Fresh temp memory-card dir per scenario | Same start state every run. |
| RNG | Nothing to seed | The game RNG is a fixed table walked by an index, seeded to 0 at boot (`vendor/dw3_decomp/src/engine/system/main.c`, `random.c`). No host entropy feeds it; host clocks in `cdfs.c`/`memcard_host.c` only time log lines. A scenario is therefore a pure function of the pad frames. |

Recording format (`tools/replay/scenarios/*.rec`, generated by
`tools/replay/gen_scenarios.py`, or recorded by hand with
`DW3_REPLAY_RECORD`):

```
pad  <frame> <hexmask>   hold this raw mask from this frame (START 0x8, DOWN 0x40, CROSS 0x4000)
shot <frame> <name>      checkpoint
end  <frame>             exit(0)
```

## Scenarios

| Scenario | Disc | Steps |
|---|---|---|
| `us-title` | US | boot, Start skips the opening movie, title (PRESS START), Start, menu (New Game / Options / Load Game) |
| `eu-lang-en/fr/de/it/es` | EU | language select, move the cursor to the language, confirm, title, Start, localized menu |

Checkpoints: `select-default`, `select-cursor` (EU), `title`, `menu`.

## Not covered (open under P6.15)

- The Switch build and Ryubing. The hook is in the PC host pad layer; the
  Switch input path (`platforms/switch`) has no replay hook yet.
- Anything past the title menu: New Game, field, battle, menus, save/load,
  restart. Add recordings with `DW3_REPLAY_RECORD` or extend
  `gen_scenarios.py`. No-input waits are fine; waits that depend on movies are
  not (see below).
- Movies. PSY-Z's captured frame is garbled for RGB24 movie frames in this
  setup, and the scenarios skip the movie with Start. FMV and audio are not
  checked at all (`SDL_AUDIODRIVER=dummy`).
- Cross-machine references. The threshold is a guess for other drivers, not
  measured; references made on one machine have not been tried on another.
- A single changed pixel is below the threshold by design.
- Timing of the skip presses (the Start pulses before the title) was tuned by
  looking at the run; if the boot sequence changes length the recordings need
  new frame numbers. A failing `title` checkpoint is the signal.
- No CI job yet (needs the owner's discs).
