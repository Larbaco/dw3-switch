# P5.3 / P10.2 — Switch applet lifecycle: HOME exit, focus, sleep (2026-10-16)

Status: the HOME exit path (P5.3) is wired and owner-verified on hardware. The
focus / sleep half (P10.2) is documented here; the guarded wiring landed in
`platforms/switch/source/boot_main.c` on 2026-10-16 and stays
**hardware-unverified** until the P10.2 OLED smoke below runs.

## What hbmenu homebrew actually is

Hbmenu starts every `.nro` through [nx-hbloader], and hbloader hands the loaded
NRO **`AppletType_LibraryApplet`** (`EntryType_AppletType` in hbloader's config
table, [nx-hbloader main.c]). Consequences:

- libnx connects through `appletAE` (`OpenLibraryAppletProxy`), not `appletOE`.
- `appletSetFocusHandlingMode` is **not available**: libnx's wrapper rejects
  every non-`AppletType_Application` with `LibnxError_NotInitialized`
  ([libnx applet.c]). The Application-only default focus handling (suspend on
  HOME open / sleep) does not run for us; AM suspends backgrounded applets by
  policy instead.
- `appletLockExit` / `appletUnlockExit` are plain `ISelfController` cmds (1/2)
  with no type check in libnx, and [switchbrew] documents `LockExit` for
  "pressing X to close in HOME Menu for an application **or HOME button for an
  applet**": while locked, the system shows the "waiting…" dialog instead of
  killing the process, for **15 seconds, then force-terminates**. Our boot
  calls it (`appletLockExit OK` in the hardware log) and unlocks before
  returning from `main`.
- `appletNotifyRunning` is skipped (Application-only), matching how homebrew
  boots already behave.

The block count / "Applet Mode" footnote in hbmenu is about heap limits
(hbloader reads `applet_heap_size`), not about which messages arrive — the
applet message surface is the one below.

## Event map: what signals what

| Event | System signal | libnx surface | Our wiring |
|---|---|---|---|
| Exit request (close app from the HOME quick menu) | `AppletMessage_ExitRequest` (4) | `appletMainLoop()` returns **false** ([libnx applet.c]; `appletGetMessage` first does `eventWait(..., 0)`, so the drain is non-blocking) | `dw3_nx_service_applet_quit()` in `platforms/switch/source/boot_main.c` — drains up to 4 messages per vsync, sets `dw3_nx_set_quit_requested()` → `Psyz_QuitRequested()`, flushes `memcard_host_flush_all()`, and the patched game loop (`port/patches/0010`) returns from `dw3_game_main()` |
| Focus loss (HOME menu open **or console asleep**) | `AppletMessage_FocusStateChanged` (15) → `ICommonStateGetter::GetCurrentFocusState` | `appletGetFocusState()` (libnx caches the value when it processes msg 15 in our drain): `InFocus`=1, `OutOfFocus`=2 (LibraryApplet overlay), `Background`=3 ([switchbrew FocusState]) | New `dw3_nx_service_applet_focus()` (see below) |
| Resume of a suspended applet | `AppletMessage_Resume` (16), gated by `appletSetRestartMessageEnabled` | `AppletHookType_OnResume` via `appletHook` | Not wired — the FocusStateChanged → `InFocus` transition covers it (see the open section) |
| Docked / handheld | `AppletMessage_OperationModeChanged` (30) | `appletGetOperationMode()` (libnx enables `SetOperationModeChangedNotification(1)` at init) | `dw3_nx_gpu_update_mode()` polls the cached value per frame (P10.3), no new plumbing needed |
| Performance mode | `AppletMessage_PerformanceModeChanged` (31) | `appletGetPerformanceMode()` | not consumed |

Sleep itself has dedicated `AppletMessage` ids on switchbrew (25
`RequestToPrepareSleep`, 26 `FinishedSleepSequence`, 27/28 temperature/battery,
29 `AutoPowerDown`) but libnx neither wraps nor handles them in
`appletProcessMessage`, and they are not part of a normal Application/applet
message feed — do **not** build sleep handling on them. Treat sleep as
"Background focus + process suspended".

## Where the loop and flush hooks live

- The **only** applet drain is the vsync pump: `Psyz_SetVSyncCb(dw3_nx_vsync_pump)`
  in `boot_main.c` calls `dw3_nx_service_applet_quit()` (exit) and
  `dw3_nx_service_applet_focus()` (focus/sleep) per frame. There is no second
  thread to coordinate: PSY-Z runs this callback on the game thread, the same
  thread that drives `MemCard*`, so the flush below cannot race a save write.
- `Psyz_QuitRequested` is **exit-only** (message 4). Focus loss must not set
  it: opening the HOME menu is recoverable, quitting would end the session
  while the player is only browsing the quick menu. The PC host disagrees with
  focus loss too — its window-close flow stays `Psyz_QuitRequested`
  (`platforms/pc/src/main.c`), and nothing else.
- Flush points (`port/memcard`): write-section end (`flush_if_dirty` on the
  next non-write `MemCard*` call), HOME exit drain, focus-loss transition
  (new), `memcard_host_shutdown` after `dw3_game_main`, and `atexit`. All
  resolve to `memcard_host_flush_all()` → rename-atomic `saveN.bin` writes,
  no-op when the slots are clean — so calling it "too often" is harmless.

## Focus / sleep wiring (this branch, hardware-unverified)

`dw3_nx_service_applet_focus()` runs after the exit drain, on every vsync:

1. Reads the libnx-cached `appletGetFocusState()`.
2. On `OutOfFocus`/`Background` (transition into out-of-focus, once):
   log the state, `Psyz_AudioPause()` (mutes the audren pull after the ~90 ms
   of queued wavebufs), `memcard_host_flush_all()`.
3. On return to `InFocus`: `Psyz_AudioUnpause()` and log the transition.
4. A `static` gap flag marks that out-of-focus pumps fell inside the current
   60-pump `frame_dt.h` window; that window gets dt clamped to the 1 s
   baseline with an `INFOF` line instead of letting a sleep gap reach the
   `fps ~` debug overlay / mem budget stats.

Rationale per pointer:

- The flush-on-focus-loss is a best effort. AM may suspend the process before
  our next pump consumes the state change — the flush is only guaranteed for
  HOME-exit (message 4, `appletLockExit` window) and clean shutdown.
  Sleep-mid-write-section is safe by construction: saves live in RAM until the
  next flush point, and flushes are rename-atomic, so a mid-flight write
  section resumes and flushes later (the same flag covers it).
- Focus loss → quit is deliberately NOT implemented. Message 4 remains the
  only source of `Psyz_QuitRequested`.
- A sleep gap reaches `Psyz_OsNowUs` consumers too (PSY-Z scheduler bell
  cadence, movie pacing budgets). Whether the ARM tick counts through
  suspension is uncharacterized here; the `appletGetProgramTotalActiveTime`
  ([6.0.0+], excludes suspended time) exists in libnx and is the cleanest
  evidence source if the smoke shows real gaps. That characterization is not
  done yet — the dt clamp on the host stats is the only consumer of the gap
  today ([frame_dt.h] feeds logs + the debug overlay, not game logic).

## Was anything verified?

- Exit flush + clean process exit on hardware: preview.20 nxlink log observed
  `applet exit: flat saves flushed` and code 0
  ([P5.3_FLAT_SAVE.md]) — that is the `appletMainLoop` false path working.
- Save→HOME-X→relaunch→Continue on OLED, US and EU (**2026-10-15, #171**,
  [P3_GATE.md]): the HOME exit flush chain end-to-end in both builds.
- The focus/sleep transitions in `dw3_nx_service_applet_focus()` have never
  run on hardware (this branch). Everything above that observes is
  platform documentation; treat as unverified until the smoke below passes.

## P10.2 OLED smoke (what "hardware-verified" means here)

Same run covers US and EU (`tools/build_switch_game.sh [--eu]`), from hbmenu or
NetLoader (Y), nxlink stdio on:

1. Enter gameplay, then press HOME: expect `applet focus: ... state=3`
   (Background), audio cut after <0.1 s, `applet focus` flush lines when a
   save is dirty; the game is still running after returning from HOME
   (audio back on `state=1`, no in-game time jump: the next `frame dt us=`
   window is clamped).
2. Sleep (power button, handheld) mid-session, wake, keep playing: same
   transition pair plus no STR/CD hiccup cell (movie and battle FPS unchanged).
3. HOME during the save bar (write section): `saveN.bin` still valid after the
   exit — either the focus flush or the exit flush lands the flat; Continue
   reloads without quarantining a `.bad` flat.
4. `appletGetProgramTotalActiveTime` delta across sleep if a gap test is
   wanted for the PSY-Z clock question.

Record results as preview notes in [P5.3_FLAT_SAVE.md] and tick/rewrite
[ROADMAP.md] P10.2.

## Open / not addressed here

- `appletHook(AppletHookType_OnResume)` + `appletSetRestartMessageEnabled(true)`
  is the alternative resume signal; not wired because the focus transition
  already covers it and both paths would need the same smoke.
- Whether AM honors `SetOutOfFocusSuspendingEnabled(false)`-style non-suspend
  for LibraryApplets is unknown here; we want suspend-to-stay (a retail-like
  pause), so nothing to try.
- P10.3 (dock/undock stability) shares `dw3_nx_gpu_update_mode` but has its
  own gate; operation-mode plumbing is already correct (libnx enables the
  notification at init).
- P10.5 applets (`swkbd`...) use `appletGetLibraryAppletLaunchableEvent`
  territory — out of scope for this note.
