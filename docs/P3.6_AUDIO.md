## Call graph (game)

```
main / boot
  SsInit()                          # engine/system/main.c
  …
  SOUND.init → initSound()          # sound.c
    SsSetTableSize(seqTable, 6, 16)
    SsSetTickMode(SS_NOTICK)        # US: manual ticks only
    SsStart2()
    SsSetMVol / SsSetSerialAttr / SsSetSerialVol
    SsUtSetReverbType(STUDIO_B) / Depth(0,0) / ReverbOn
    loadSoundBankInto(0, 1)         # system bank → slot 0 (blocks)

GFX.startVSyncCallback()
  VSyncCallback(vsyncCallback)      # display.c
    … time counters, vsyncFunc, PutDispEnv …
    SsSeqCalledTbyT()               # every vblank under SS_NOTICK

Modes (title / field / battle / menus)
  SOUND.loadBank(id)                # slots 1↔2 alternate
  SOUND.updateLoading()             # FILE_CACHE + VAB/SEP open
  SOUND.playSound(packed)           # SEP or SsUtKeyOn
  SOUND.stopSound / fadeOutSound / stopAll
```

### Bank load pipeline (`updateSoundLoading`)

| State | Action |
|---|---|
| `SOUND_LOAD_HEAD` | Copy head archive → slot buffer; `SsVabOpenHeadSticky(vh, slot, spuAddr)` |
| `SOUND_LOAD_BODY` | `SsVabTransBody(vb, vabId)` |
| `SOUND_LOAD_TRANSFER` | Wait `SsVabTransCompleted(0)`; for each SEP index: `SsSepOpen(..., vabId, SOUND_SEP_COUNT)` (`16`) |

Three slots: **0** = system bank `1` (always); **1/2** swap for stage /
mode banks. Fixed SPU sticky addresses in `SOUND_SPU_ADDRS[]`.

### Packed sound ids (`playSound`)

| Bit | Meaning |
|---|---|
| 31 | `1` = `SsUtKeyOn` one-shot; `0` = SEP sequence |
| 30 | Exclusive “music”: stop previous exclusive |
| 18–24 | Bank id (must be loaded) |
| key-on | prog / tone / note |
| sequence | SEQ index + SEP track |

Helpers: `MUSIC(bank, n) = 0x60000000 | bank<<18 | n` (exclusive SEP).
Shared SFX constants live in `include/engine/sound.h` (e.g.
`SOUND_SELECT = 0x8004503C` → key-on from bank 1).

### Mode entry points (validation targets)

| Case | Path | APIs |
|---|---|---|
| Title music | `STDWTITL` loads bank `0x47`, plays `MUSIC(0x47, 0)` | `loadBank` → `SsSepPlay` |
| Field switch | Stage sets `FIELDSTG_state.music = MUSIC(bank, n)`; bank load on enter | SEP stop/play + bank swap |
| Battle SFX | Fight overlays + system bank key-ons / battle music banks | `SsUtKeyOn` + SEP |
| Fades | `fadeOutSound` | `SsSepSetDecrescendo(..., 0x80, 0x3C)` (~1 s NTSC) |

No direct `libspu` from game code — only libsnd (+ XA/STR via libcd /
libpress for opening movies; P3.7 play+skip proven, owner DAC listen
still open on main).

| `SsVabOpenHeadSticky` / `TransBody` / `TransCompleted` / `Close` | VAB | `vs_vh.c`, `vs_vtb*.c`, … |

path `display.c` installs.

### Declared but not really playable (blocker core)

`SsSepOpen` wires `SsFCALL.*` to MIDI handlers. Those handlers (and the
SEQ reader) are **stubs** in `vendor/psyz/psyz/src/psyz/libsnd.c`
(`NOT_IMPLEMENTED`), because upstream decomp still has `INCLUDE_ASM` for
the real bodies:

| Symbol | Upstream | Host effect |
|---|---|---|
| `_SsSeqPlay` / `_SsGetSeqData` / … | `midiread.c` ASM | SEP advances do nothing |
| `_SsNoteOn` / program / CC / NRPN / … | `midinote.c`, `midicc.c`, … ASM | No MIDI → voice |
| `_SsSndTempo` | `tempo.c` ASM | Stub |
| `_SsVmGetSeqVol` (partial) | `vm_seq.c` ASM | Stub in `libsnd.c` |

`play.c` is a one-liner: `_SsSndPlay` → `_SsSeqPlay`. So **`SsSeqCalledTbyT`
runs, but SEP music cannot sequence notes** until `_SsSeqPlay` (and note-on
path) are real C or otherwise provided.

`SsUtKeyOn` has decomp C and may key voices if VAB transfer + VM are
healthy — closest path for battle/menu SFX before SEP works. Still depends
on sticky VAB load and SPU sample RAM.

### Port-only stub already present

| Symbol | Where | Why |
|---|---|---|
| `SsSepSetDecrescendo` | `port/psyz_missing/psyz_missing.c` | `ssdecres.c` is `INCLUDE_ASM` and **not** in PSY-Z `CMakeLists.txt` |

## Host pump requirements

1. **Vblank must fire** so `vsyncCallback` → `SsSeqCalledTbyT` runs once
   per frame under `SS_NOTICK` (US). Headless / unlocked frame rates need
   an explicit vblank inject if the SDL present loop is skipped.
2. **`SsStart2` + NOTICK:** game owns the tick; do not also rely on
   libsnd auto-installing a second tick callback for US.
3. **Audio device:** `Psyz_AudioInit` must run (today often via CD/SPU
   bring-up). Without SDL audio, mixer still advances only if something
   pulls samples — verify PC host actually opens the device in title boot
   (dummy driver OK for tick proof; real DAC for listen checks).
4. **FILE_CACHE / runtime:** VAB/SEP bytes come from numbered files
   (`SOUND_FILES_*` → file ids). Title bank `0x47` → US files in
   `SOUND_FILES_47` (`sound.c`, file ids **2186/2185** VH/VB + SEP).
   Runtime layout from P1.6 must contain those ids.
5. **Thread safety:** SDL audio callback locks `Psyz_AudioLock`; vsync /
   game thread must not race SPU regs unsafely (PSY-Z already locks in
   several CD/SPU paths — keep A6 changes inside that model).

## Tick probe (this wave — proven)

`tools/audio_tick_probe/probe_ss_seq_called.sh` runs `gdb` against a
local `dw3-pc` and counts hits on `SsSeqCalledTbyT` until `--hits N`
(default 120).

Evidence (2026-10-10, bringup binary + `runtime/us`, no psyz edits):

- `AUDIO_TICK_HITS=120` before exit
- Log also showed `Psyz_AudioInit OK` (dummy driver fallback when no DAC)
- `ConfigureVSync` targeting ~59.94 Hz with frame limiter
- Symbols present: `SsSeqCalledTbyT`, `_SsSeqPlay`, `vsyncCallback`

So the **host pump is alive** on title boot. Remaining work is making
SEP/`_SsSeqPlay` actually emit notes — not wiring the vsync call.
