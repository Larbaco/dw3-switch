## Call graph (game)

```
main / boot
  SsInit()                          # engine/system/main.c
  …
  SOUND.init → initSound()          # sound.c
    SsSetTableSize(seqTable, 6, 16)
    SsSetTickMode(SS_NOTICK)        # US: manual ticks only
    SsStart2()
    …
    loadSoundBankInto(0, 1)         # system bank → slot 0

GFX.startVSyncCallback()
  VSyncCallback(vsyncCallback)      # display.c
    SsSeqCalledTbyT()               # every vblank under SS_NOTICK

Modes (title / field / battle / menus)
  SOUND.loadBank(id)                # slots 1↔2 alternate
  SOUND.updateLoading()             # FILE_CACHE + VAB/SEP open
  SOUND.playSound(packed)           # SEP or SsUtKeyOn
```

### Mode entry points

| Case | Path | APIs |
|---|---|---|
| Title music | `STDWTITL` loads bank `0x47`, plays `MUSIC(0x47, 0)` | `loadBank` → `SsSepPlay` |
| Field switch | Stage sets `FIELDSTG_state.music = MUSIC(bank, n)` | SEP stop/play + bank swap |
| Battle SFX | Fight overlays + system bank key-ons | `SsUtKeyOn` + SEP |
| Fades | `fadeOutSound` | `SsSepSetDecrescendo(..., 0x80, 0x3C)` |

### Honesty

`INCLUDE_ASM`. Host player is **`psyz/src/psyz/midiread_host.c`**:

- Logic ported from Xeeynamo/sotn-decomp `seqread.c` (MIT) onto PSY-Z’s

### Fix — tech SFX silences all audio (#188, 2026-10-22)

Report: EU v0.6.5-preview.29 on OLED. After a tech in battle all audio
stops until a map change; another tech plays only its own SFX.

Cause (code reading + unit test): when an ADPCM block flagged loop-end
without repeat ran out, `spu_voice.h` cleared `active` but left
`env_vol` at the sustain level. The mixer skips inactive voices, so ENVX
(`volumex`) never read 0 again. libsnd frees a voice only when ENVX is 0
(`_SsVmFlush`), so one-shot SFX leaked voices until `_SsVmAlloc` had
none left and `SsUtKeyOn` failed. Map change recovers via
`SOUND.stopAll()`.

Fix: psyz `2caa505` backports upstream `a7862ba` (#205). The voice is
released with `env_vol = 0`, `env_state = ADSR_OFF`. Test
`spu::AdpcmLoopEndWithoutRepeatZeroesEnvx` fails before the fix (ENVX
0x3FFF) and passes after it. The rest of the psyz suite is unchanged
(same pre-existing failures). Battle smoke (`DW3_FORCE_ENCOUNTER`) stays
non-silent for 28 s. Not yet verified: the reported tech in game and on
Switch hardware.

### Fix — music plays once and goes silent (2026-10-23, preview.30-rc7)

Report: Switch OLED, US rc7. Background music plays one pass and stops;
SFX keep working; sleeping at the inn restarts the music for one more pass;
battle music does the same. The rc7 log
(`dw3-preview30-rc7-out/dw3.log`) has 23 `SEP end-of-track seq=N tr=N`
lines and no loop lines.

Cause: PS1 SEQ/SEP loops are NRPN events, not the end-of-track meta. The
game calls `SsSepPlay(..., SSPLAY_PLAY, l_count 1)` (`sound.c`), so the music
relies on the data: CC#99 = 20 starts the loop, CC#6 (Data Entry) right after
it carries the repeat count (127 = forever), CC#99 = 30 ends it and jumps back
(`_SsContNrpn2`). The host reader `midiread_host.c` kept its Data Entry
handler as a no-op that discarded the value (its count capture sat in the
CC#98 handler, which these songs do not use for it), so `unk1D` stayed 0, the
loop end fell through, and the track ran into `FF 2F` and stopped
(`l_count` 1 = one pass). Sound effects are one-shot and never noticed.

Verified against retail, not only sotn-decomp: the US executable's
`_SsContDataEntry` (`0x800307F8`) starts with `if (unk1C == 1 && unk15 == 0)
{ unk1D = val; unk1C = 0; unk15 = 1; }`, `_SsContNrpn2` (`0x80031048`) is the
loop start / end quoted above (start position stored at offset 0x08), and the
end-of-track handler (`0x8002F7F4`) restarts at `read_pos` while passes are
left (`l_count` 0 = forever). Disassembled from the owner's own
`SLUS_014.36`, not committed.

Fix (psyz `dw3-seq-nrpn-loop`): the CC#6 / CC#98 / CC#99 / CC#100 / CC#101
handlers use the retail fields (`unk15`, `unk1B`, `fn_idx`, `unk1E`, `unk1F`,
loop start in `next_sep_pos`); the host also stopped writing `unk10`, which
retail uses as a pointer (the play-to-position end). End-of-track restarts at
`read_pos` like retail. Log lines: `SEP loop count N`, `SEP loop end -> loop
start (count infinite | N left)`, and `SEP NRPN VAB attr I=V ... ignored`.

Not done: Data Entry also completes an RPN pair (pitch bend range of the
sounding voices) and an NRPN pair (`SsFCALL.ccentry[fn_idx]`, the VAB
attribute setters). The host consumes and drops both, as before: the
`_SsSetNrpnVabAttr*` bodies in psyz are `NOT_IMPLEMENTED` stubs. The title and
field music do send NRPN 16 with attributes 15 and 16 (reverb type and depth,
for example `15=3`, `16=48`), so their reverb setup is still not applied.
Chained sequences (`unk22`, `SsSeqSetNext`) and the user NRPN callback
(CC#99 = 40) are not ported either.

Evidence:

* `psyz/tests/test_libsnd_loop.c`, group `snd_loop` (hand-made SEQ data
  through `SsSeqOpen` / `SsSeqPlay` / `SsSeqCalledTbyT`): plain track plays
  once; NRPN count 3 runs the body three times; count 1 once; count 127 never
  ends (more than 5 passes in 1000 ticks, no `FF 2F`) and again after
  `SsSeqStop` and a new play; end-of-track with `l_count` 0 restarts and with
  `l_count` 3 plays three times. Before the fix `nrpn_loop_runs_count_times`,
  `nrpn_loop_127_never_ends` and `nrpn_loop_127_survives_stop_and_replay`
  fail (1 pass, then end-of-track); after it all 7 pass.
* Replay scenarios `us-music-loop` / `eu-music-loop`
  ([P6.15_REPLAY_TESTS.md](P6.15_REPLAY_TESTS.md)): the field music idles for
  3000 frames. Fixed build, both discs PASS: `SEP loop count 127 seq=2 tr=0`,
  US 3 / EU 4 `SEP loop end -> loop start (count infinite)`, no
  `end-of-track`. Build from before the fix, both discs FAIL: one `SEP
  end-of-track seq=2 tr=0` shortly after frame 600, no loop line. The
  US title song (bank `0x47`, `SsSepPlay ... sep=0`) has no loop count in
  its data: it plays once and the title restarts it after the attract movie
  (no `end-of-track` in 8400 idle frames), so the field is where the bug shows
  on PC. The EU title song does carry the loop (`SEP loop count 127`) and
  repeats with the fix.
* Replay scenarios `us-battle-music-loop` / `eu-battle-music-loop`: the same
  on the battle theme (a random battle, then idle in it until frame 7500).
  The theme (US bank 2 `sep=0`, `seq=3 tr=0`) logs `SEP loop count 127` and a
  loop-end jump back on both discs with the fix; the build from before it
  logs `SEP end-of-track seq=3 tr=0` and no jump on both discs (the music
  stops, as the owner heard). The forced-encounter harness
  (`DW3_FORCE_ENCOUNTER`) plays a short one-shot battle sound (bank 1,
  `sep=10`) instead of the theme, so it cannot show this.
* PC only (Xvfb, SDL dummy audio, log verdicts: no sound was listened to).
  Not yet checked on the Switch OLED.
