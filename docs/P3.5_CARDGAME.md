## Root cause (post-prize SEGV)

`CARDGAME_updateScene` case 1 does `items[0]->setState(items[0], 3)`.
Engine `TASK_KILL` is `3`, so `executeTask` destroys the battle child and
clears `items[0]`. An earlier host fprintf in case 2 then dereferenced
NULL → SEGV. Fix: log return fields in case 1 **before** `setState(3)`;
case 2 only `requestMode` (vanilla-safe).
