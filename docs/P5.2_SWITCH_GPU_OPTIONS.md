## Present path (current)

```
Draw_PushPrim (switch_gpu.c)
  FIGHTSTG + !soft → nx_mesh enqueue (gpu-solid ORs NOTEXTURE)
  else → software RasterTriangle

Draw_ClearImage → CPU VRAM clear + dw3_nx_mesh_clear_rect (same RGB)

Psyz_VideoVSync → dw3_nx_gpu_present (nx_gpu.c)
  1. letterbox glClear black
  2. if mesh had content: blit mesh FBO, then UI with black-discard
  3. else: opaque CPU VRAM blit
  4. eglSwapBuffers
```

UI discard (`c.r+c.g+c.b < 0.002`) punches through to the mesh FBO whenever
CPU VRAM texels are zero — which is expected when 3D skipped the software
raster.

| **H4** | mesh+ui black-discard over empty/clear FBO | Amplifies H1–H3 into a full-screen solid | `mesh_only_diag` present: if FBO has colour, it must show |

gpu-tex after solid colour is proven.

## Framework survey (honest)

Constraints from `AGENTS.md`: prefer PSY-Z shim; PC bring-up first; no
matching-build cargo; no overclock; Switch host thin; do not rewrite the
game into a new engine; no emulator wrappers.

| Option | Fit for PS1 OT→triangles | Effort | Risk | Verdict |
|---|---|---|---|---|
| **A. Fix current GLES3 `nx_mesh` / `nx_gpu`** | Direct; shaders already from PSY-Z `sdl3_gl` | Days | Image/band bugs (current) | **Default. Do this.** |
| **B. deko3d** (homebrew low-level) | Can draw tris; rewrite present + shaders + upload | Weeks | Loses GLES/`sdl3_gl` portability; no proof GLES is guilty | Park until A paints colour and GLES is profiled guilty |
| **C. Other homebrew GL wrappers** (thin EGL helpers, glad-like loaders) | Same GLES underneath | Low–med | Does not fix band/sample/composite | Not justified; we already have working EGL ES3 |
| **D. Heavier stacks** (full vk ports, engine swaps, emulator GPU) | Wrong layer | Months | Violates mission | **Out of scope** |

**Recommendation:** another framework is **not** justified for the blue.
FPS on gpu-tex (~59 Hz) already beats soft (~53 Hz) — the path is fast
enough when it runs; it is **wrong colour**, not “need a faster API”.
