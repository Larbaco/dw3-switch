# P7.9 Battle menu memory

Status (2026-10-22): part A is implemented and tested on the PC build (US and
EU); it needs the OLED check below. Part B (reordering techniques per
Digimon, persisted) is investigated and deferred, see
[Part B](#part-b-reordering-techniques-deferred).

## What it does

The player's turn opens the battle command menu (Fight / Tech / DV / Tag /
Item / Run) with the cursor on Fight every time, and the technique list on
its first technique. With the option on:

- The command menu opens on the **last command picked**: use Tech once and
  the next turn opens on Tech, so Tech, Cross, Cross uses a technique.
- With level 2 the technique list opens on the **technique this partner
  used last** (turned to its page when it is on the second one).

It is a **file-only option** (no row on the Options screen), **off by
default**:

```
# sdmc:/switch/dw3/us/port_options.cfg  (or eu/; PC: runtime/us|eu/port_options.cfg)
battle_menu_memory=1
```

| Value | Behaviour |
|---|---|
| absent, `0`, or anything else | Off: the original game, bit-identical |
| `1` | The command menu remembers the command |
| `2` | `1`, and the technique list remembers the technique (per partner) |

The Options screen keeps the key when it rewrites the file (unknown keys are
preserved, see [PORT_OPTIONS.md](PORT_OPTIONS.md#persistence)); the key can
be added by hand-editing the file on the SD card or the PC runtime dir.

## Decisions

| Question | Choice | Why |
|---|---|---|
| Off or on by default | **Off** | The existing replay scenarios press Down once at the start of every battle (`two-battles`: "Fight -> Tech" in battle 2). With the memory on, battle 2 opens on Tech and Down moves to DV, so `battle2-menu` / `battle2-tech` and the rest of that scenario diverge from their references. A default that changes recorded runs is not "bit-identical when off", and the owner asked for the roadmap item as an option. The cost is that nobody sees it without editing a file; the trade-off is on purpose: the Options screen is full (below) and a visible default change in a battle menu should be the owner's call after the OLED check. Turning it on by default later is a one-line change in `dw3_port_battle_menu_mode` plus new references for the replay scenarios that press Down. |
| A row on the Options screen | **No** | The screen has 7 rows sharing one window (a row is 42 px high on a 48 px pitch, `platforms/pc/src/title_overlay_art.c`, `DW3_TITLE_OPTION_ROWS`), each with its own art word and description; an 8th row would need a smaller pitch, a scroll or a second page, which is a rework of P9.2 and of the retained cache's layout test, out of scope here. A file-only key needs only `dw3_port_options_file_int` (the loaded file is kept in memory anyway). If the owner wants a row later, it is one more `Dw3PortOptStub` plus that layout work. |
| Scope | **The session** (the process), for the command across battles and partners; the technique per party member | "Techniques stays on Techniques" is most useful across fights: the first turn of the next battle opens on it too (`<v>-p79-memory-two-battles`). The technique is per partner because two partners have different lists. Not saved: see Part B and P7.12 (a save field needs the format frozen); a relaunch starts on Fight again, which is also the safe state. |
| Which commands are remembered | Fight, Tech, Item, Tag (switch) | **Run** ends the turn or the battle and a failed run would make the next accidental double Cross run again; **Digivolve** is greyed out for the form it leads to. Neither changes the memory, the last other command stays. |
| A remembered line that is not usable | Falls back to Fight | Asleep (Fight / Tech / DV greyed) and `FIGHTER_NO_DIGIVOLVE` (DV greyed) already start on the greyed Fight in the original; the memory never puts the cursor on a greyed line. A remembered technique that is not in the list (another form), or that the fighter lacks the MP for, falls back to the first line. |
| Cancel from a sub-menu | Unchanged | Triangle in the technique list already returns to the command menu on Tech in the original (`PlayerTurn.command`); the patch changes only the value a *new turn* starts from. |

## Implementation

Patch `0067-PORT_HOST-p79-battle-menu-memory.patch` (not upstream-bound, all
hooks inside `#if PORT_HOST`):

| Place | Hook |
|---|---|
| `battle_mode/player_turn.c`, `FIGHTSTG_updatePlayerTurn` substate 0 step 0 | `task->command = dw3_port_battle_menu_start_command()` instead of `BATTLE_COMMAND_ATTACK` (the original resets the command to Attack at the start of each turn) |
| `runCommandMenu` | `FIGHTSTG_createCommandMenu(dw3_port_battle_menu_open_command(task->command, asleep, noDigivolve), ...)`: the line the cursor starts on |
| `runCommandMenu`, where the pick is stored | `dw3_port_battle_menu_command_picked(result)` |
| `runTechMenu`, where the pick is stored | `dw3_port_battle_menu_tech_picked(member, tech)` |
| `battle_mode/tech_menu.c`, `FIGHTSTG_updateTechMenu` init | looks up `dw3_port_battle_menu_tech_wanted(member)` in the list, sets `task->page`, the cursor's `params.count` and `sel` before `FIGHTSTG_showTechPage` |
| same | test hook `DW3_EXTRA_TECHS=<id>,...` appends techniques to the list (the stock Kotemon has Hot Head only; PC environment, no-op when unset, not on Switch) |

State and policy: `port/battle_menu/battle_menu_memory.c` and
`port/include/port_battle_menu.h` (linked in `dw3_port_options`, so PC and
Switch both have it). The key is read through
`dw3_port_options_file_int(key, default)` in `port/options/port_options.c`.
The memory is two statics (a command, eight technique ids). With the key
absent every function returns the original value (Attack, the command it was
given, the first line) and logs nothing, so the game state, the RNG and the
frames are those of a build without the patch. Same code on the US and EU
discs.

Log lines (the replay tests match them; psyz_log, so they are in
`sdmc:/switch/dw3/dw3.log` too):

```
dw3-battle-menu: command menu opens on Attack
dw3-battle-menu: remembered command Techniques
dw3-battle-menu: remembered technique 54 for partner 0
dw3-battle-menu: command menu opens on Techniques (remembered)
dw3-battle-menu: technique list of partner 0 opens on technique 54 (page 0, line 1, remembered)
```

Off writes none of them.

## OLED check (the owner)

Needs the Switch build; the cursor bar and the blinking square are the part
the PC captures cannot show.

1. Put `battle_menu_memory=2` in `sdmc:/switch/dw3/<us|eu>/port_options.cfg`
   (copy it first; the file is written by the Options screen with an
   `end=1` line last, keep the other keys and put the new line before `end=1`).
2. Fight a random battle. Turn 1: Tech, pick the second technique. Turn 2:
   the menu must open with the cursor on Tech; Cross opens the list with the
   cursor on that same technique.
3. Win, fight another battle: its first menu opens on Tech.
4. Use Item, then next turn: opens on Item. Run (if it fails): the next turn
   does not open on Run.
5. Remove the line (or set 0): Fight is the start again.
6. `sdmc:/switch/dw3/dw3.log` shows the `dw3-battle-menu:` lines.

## Part B: reordering techniques (deferred)

Goal: let the player reorder the technique list per Digimon and keep it.

Findings:

- The list is built at menu open from the partner's entry
  (`listSlotTechs` in `tech_menu.c`: the entry's six skills in table order,
  the signature technique of a temporary Digimon, then the ones other entries
  can pass on). There is no stored order; reordering means a per-Digimon
  permutation applied after that list, and a UI to edit it (a new mode in the
  technique menu, Select or a shoulder button, which the original does not
  use there except L1 / R1 for pages).
- The save is the PS1 card image: 32768 bytes, header, icons, info and three
  slots with checksums (`port/memcard/README.md`); `memcard_host` treats any
  other size as corrupt and quarantines it (`saveN.bin.bad`). Extra bytes in
  the file would break that and the compatibility with emulator cards (P9.6)
  and the PS1 game, and the slots have no known free space we may take.
  Changing the slot layout is the P7.12 question and must wait for a
  frozen format with a migration.
- A **sidecar** avoids all of it. `saveN.name` already is one. Design: a
  text file `saveN.order` beside `saveN.bin`, written with the same
  rename-atomic helper as the options file, one line per Digimon id with the
  skill ids in the wanted order (`386=53,54,55`), applied as a stable
  permutation of the list (skills not in the file keep their place at the
  end, ids no longer in the list are dropped). Questions it leaves open:
  three slots share one `saveN.bin`, so the file would be keyed by slot
  (`slot=1;386=...`) or by the save's own identity, and loading another slot
  or an older save must not apply a stranger's order; copying `saveN.bin`
  alone (the P9.6 tool, a backup) loses the order; and the order must be
  written when the save is, not when the player edits, or a game that is not
  saved would keep an order the save does not have.

Decision: not implemented in this change. The memory (part A) is independent
of it; a reorder UI plus the sidecar is a change of its own, after the
owner confirms that reordering is wanted over the memory. The roadmap item
stays open for it.

## Results

Measured 2026-10-22 on the PC build (sdl3_gpu under Xvfb) with the patched
decomp, US and EU. Evidence (captures, logs) is in
`/mnt/windows/Jogos/dw3-switch/tmp/evidence/p79/` (not in git).

- Full default-tier replay suite, `tools/replay_tests.sh` against
  `~/.cache/dw3-switch/replay-refs`, references unchanged: **469 checks, 0
  failed**. Main was 421 checks, 0 failed; the 48 new checks are the 12
  log-only `p79` scenarios (4 checks each). Every pre-existing scenario,
  including the picture-diff ones (`two-battles`, `options-persist`, ...), is
  identical with the feature at its default (key absent).
- The 12 `p79` scenarios, US and EU: all pass (`memory-off` and
  `memory-invalid` show no `dw3-battle-menu:` line; `command`, `tech`,
  `page2` and `two-battles` show the lines listed above).
- Unit tests, `uv run --with pytest --with pillow python -m pytest tools/tests -q`:
  all pass (new: `test_battle_menu.py`, `test_options_persist.py::test_file_only_int_key`).
- Captures of turn 2 on US and EU (`<v>-p79-compare.png` in the evidence
  folder, three runs each): memory off, the second turn's menu has the
  cursor square on Fight and Cross attacks; `=1`, the square is on Tech and
  Cross opens the list on Hot Head ("Slash with sword and fire attack");
  `=2`, the list's description is Swing Swing's ("Aim for weak point with
  slingshot"), the technique used on turn 1 (the list is turned to it; the
  cursor bar itself is a GPU callback that the PC capture does not draw).
- Why off by default, measured: the existing `us-two-battles` recording
  replayed with `battle_menu_memory=1` differs from its references at
  `battle2-menu` (11872 px, the cursor square moved) and then at
  `battle2-tech` (728129 px) and `field-after` (918077 px), because the
  recording's Down in battle 2 now moves from Tech to DV.
- Switch builds: `tools/build_switch_game.sh` (US, 9232556 bytes) and
  `--eu` (9265324 bytes) both build.
- Not covered: the OLED (checklist above), the Ryubing runner (the
  scenarios need environment hooks the NRO lacks), the other four EU
  languages (the menu text is not touched; the logic is language-free).
