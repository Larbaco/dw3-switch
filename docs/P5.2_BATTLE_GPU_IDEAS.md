# P5.2 — Battle GPU ideas (beyond approach A)

Status: design only (2026-10-11). Not a re-enable of field or battle mesh.
Companion to [P5.2_BATTLE_GPU.md](P5.2_BATTLE_GPU.md). Soft battle remains
default ON until a dump proves colour.

## Why this note exists

Owner feedback after soft-battle recovery: **the Fight picture is back**, but
**battle still lags / feels bad**. Field gate is OK. PC `sdl3_gpu` never pays
`RasterTriangle` (~1.6 ms CPU, VSync-bound). Switch Fight-menu idle still
fills ~347k bbox pixels / frame in software (~5 ms-class on a desktop census;
worse on Tegra stock clocks).

Approach A (full textured GLES mesh FBO) **flushed tens of thousands of tris**
yet produced **all-black FBO dumps** (`mesh_nonblack=0`). That is not “no
work” — it is wrong clear / UV / sample / composite. Blindly turning
`DW3_NX_MESH_SOFT_BATTLE=OFF` again is not the next move.

Constraints (do not violate):

- No overclock / no `clkrstSetClockRate` / no CPU boost.
- No upstream Xeeynamo/psyz PR; fork pin stays.
- Movies stay 150 sectors/s.
- **Field stays software** until a dedicated correct path exists.
- UI sprites stay software unless a path is proven safe.
- Do not re-enable global field mesh.

## What we already know (evidence)

| Fact | Source |
|---|---|
| Fight menu ~1115 clipped textured tris, ~347k bbox px | PC census (`battle-pc.txt`) |
| PC path: no `RasterTriangle`, ~1.6 ms CPU | same |
| preview.8 battle ~46 Hz (`~1293264` µs / 60) | OLED |
| preview.9 ungated mesh: field ~42 Hz, battle ~20 Hz + broken look | OLED |
| FIGHTSTG gate restores field look / ~60 Hz | preview.10 |
| Mesh on battle: huge `tris_flush`, FBO dump `nonblack=0` | FTP PPMs |
| Soft battle ON: picture OK, still soft-fill limited | owner |

Hypotheses for all-black (still open, ordered by likelihood):

1. Textured fragment path samples wrong (CLUT / tpage / UV / dirty-skip timing)
   → shader outputs zero while vertices submit fine.
2. Wrong double-buffer band at present/dump (`y=0` vs `y=256`).
3. Clear colour / ClearImage fills the display rect; textured draws write
   elsewhere or with zero RGB.
4. Composite: mesh+ui + black-discard over a black FBO → solid black/blue.

Any new path must falsify (1)–(4) with dumps **before** claiming FPS wins.

## Approaches

Each entry: idea, why it might beat soft `RasterTriangle` on OLED, risk,
effort, relation to the all-black FBO failure, experiment order tag.

### A. Fix the existing GLES mesh FBO (debug-first)

**Idea.** Keep `nx_mesh` architecture. Do not re-enable soft_battle=OFF for
players. Build a **debug ladder** that proves colour at each rung:

1. Force solid fragment colour (ignore texture) for battle polys → dump both
   bands (`y=0` and `y=256`).
2. Untextured gouraud only (`POLY_G*`).
3. 16-bit direct sample (no CLUT).
4. 4-bit CLUT with nearest UV (already attempted; re-verify after solid works).
5. Only then: opaque composite without discard; discard last.

Gate: `mesh_nonblack > 0` (prefer >10% of display pixels) on a deferred dump
(`prims_flushed ≥ 2000`) before any FPS claim. Keep soft_battle default ON
until then.

**Why it might win.** Removes ~347k software fill pixels — the same win PC
already has. Dirty upload already cut the preview.9 bus tax for idle Fight.

**Risk.** Image: CLUT / ABR / dither drift. Perf: if sample upload or discard
composite stays expensive, FPS can still lose even with non-black FBO
(preview.9 lesson). Field must stay gated.

**Effort.** 1–3 days for solid→gouraud proof; 3–7+ days for textured parity.

**vs all-black.** This is the direct investigation of that failure. Solid
colour isolates “FBO / viewport / band” from “sample shader”.

**Order.** **Spike #1 (GPU track)** — see Recommended spike below.

### B. Hybrid: GPU untextured / gouraud first; textured later  
(or GPU opaque, software ABR/semi)

**Idea.** Split the OT by poly class under FIGHTSTG only:

- Route `POLY_G3/G4` (and maybe flat shaded) to the mesh FBO with a trivial
  shader (vertex colour → FragColor).
- Keep `POLY_GT*` / `POLY_FT*` on software until A’s ladder reaches CLUT.
- Optional later split: opaque ABR=off on GPU; semi-trans / subtractive ABR
  stay on software VRAM, then composite carefully (no black-discard punch).

**Why it might win.** Census is mostly textured, so untextured-only is a
**small** FPS win — but it is the cheapest **correctness** probe and may
still paint backgrounds / shadows that prove the FBO. Opaque-first later
can offload the majority of bbox pixels once textured works.

**Risk.** Image: missing textured digimon / stage look if shipped early.
Ordering if opaque GPU + software semi interleave wrong.

**Effort.** 0.5–1 day untextured probe (overlaps A). Opaque/textured hybrid:
2–4 days after colour works.

**vs all-black.** Untextured path bypasses CLUT/UV — if still black, bug is
viewport/FBO/band/composite, not sampling.

**Order.** **Same as A day-1** (A’s first rungs *are* B).

### C. Tile / atlas cache (tpage + CLUT as real GL textures)

**Idea.** Stop treating the whole 1024×512 VRAM as one sample texture every
dirty frame. On `LoadImage` / CLUT touch, upload **only dirty tpage tiles**
(64×256 pages) and CLUT rows into small `GL_TEXTURE_2D` (or a texture array).
Draw with a simple GLES2/3 shader closer to PSY-Z `sdl3_gl`: UV in page
space, CLUT as 256×1 texture, OT order preserved via batch breaks on state
change.

**Why it might win.** Preview.9’s killer was full-VRAM pack+upload. Atlas
uploads are tiny; Fight-menu idle often stops touching VRAM after load
(dirty flag already helps — atlas makes the hot path even cheaper and
avoids packing RGBA8 for untouched pages).

**Risk.** Image: twin / window / STP edge cases; cache invalidation bugs →
stale textures (wrong colours) or black. Effort to mirror PS1 page math.
Still must solve composite (opaque blit vs discard).

**Effort.** 3–7 days for a battle-only atlas after A proves any GPU colour.

**vs all-black.** Orthogonal: even a perfect atlas cannot help if the
current FBO never receives fragments. Do **after** solid/untextured
nonblack>0. May *fix* black if the bug was “sample tex never valid /
wrong format” — then atlas is both fix and win.

**Order.** After A/B colour proof; before or with D.

### D. CPU transform / clip, GPU fill (batched indexed draws)

**Idea.** Keep GTE + OT walk on CPU (already paid). Emit pre-clipped
screen-space triangles into a persistent VBO/IBO (or few large buffers).
One `glDrawElements` per state bucket (texture id / ABR / dither). No
per-tri draw calls. Optionally expand quads → two tris on CPU.

**Why it might win.** Driver overhead on Switch GLES for ~1k individual
submits can dwarf fill. Batching is how `sdl3_gpu` stays cheap. Fill moves
to the GPU; CPU only memcpy’s verts.

**Risk.** Still needs a working textured/untextured shader (inherits A’s
bugs). Memory for buffers on a tight heap (P5.1). Wrong state bucketing →
sort/OT visual errors.

**Effort.** 2–4 days once a trivial shader paints colour.

**vs all-black.** Does not explain black by itself; reduces cost **after**
fragments write. Pair with A’s solid shader for a clean “batch + colour”
spike.

**Order.** Right after A solid/untextured works; can share the spike.

### E. Multithread software raster (2–3 cores) — interim, not hardware

**Idea.** Honest stopgap: keep soft_battle ON. Partition `RasterTriangle`
work by scanline bands or by OT ranges across 2–3 threads (libnx threads /
pthreads). Main thread still owns present and GTE. Barrier before VRAM
present. Optional: tile bins (16×16) with atomic ownership.

**Why it might feel better.** Fight fill is CPU-bound. Dual-core can cut
wall time toward ~half if the raster is the limiter and present is not.
No GLES correctness risk. Field untouched.

**Risk.** Race on VRAM writes if bins overlap; ABR order must stay OT-serial
within overlapping pixels (hard — prefer non-overlapping y-bands of a
**single** frame’s triangle list after sort, or accept minor visual
glitches only in spike). Cache thrash may eat the win. Not a path to PC
parity; still pays fill bandwidth.

**Effort.** 1–2 days for a banded spike with a compile flag; 3–5 days to
harden.

**vs all-black.** Independent. Safe while A is debug-black.

**Order.** **Spike #1 (soft track)** parallel to A — shippable under soft
battle if numbers win.

### F. Render mesh to low-res RT and upscale

**Idea.** Mesh FBO at 160×120 (or 256×192) inside the 320×240 band; bilinear
or nearest upscale at present. UI stays full-res software.

**Why it might win.** Fill rate and bandwidth drop ~4× for 3D. On OLED
handheld GPU, that can matter more than CPU.

**Risk.** Obvious softness / crawling on digimon edges. Still needs non-black
mesh. Composite alignment with UI becomes fiddlier.

**Effort.** 0.5–1 day **after** colour works (viewport + present scale).

**vs all-black.** Quality trade only; does not fix black. Skip until
nonblack>0.

**Order.** Late polish / emergency FPS if full-res GPU is close but over
budget.

### G. deko3d (or non-GLES API) if GLES is the bottleneck

**Idea.** Replace EGL/GLES mesh (or the whole present path) with deko3d
command buffers, or a thin vk/nvn-style layer if ever available in homebrew.

**Why it might win.** Only if profiling shows GLES driver / shader compile /
texture upload path dominates **after** fragments are correct. deko3d can
be more predictable on Tegra for homebrew.

**Risk.** Large rewrite; loses `sdl3_gl`-shaped shader portability; long
ramp; no evidence yet that GLES itself (vs wrong algorithm + full VRAM
upload) is the limiter. Field/UI still need a present story.

**Effort.** Weeks, not a spike.

**vs all-black.** Unjustified until A works in GLES and still loses to soft
on flush/upload/present counters. **Do not start now.**

**Order.** Last resort; park.

### H. Skip empty bbox / edge-walk only covered pixels in `RasterTriangle`

**Idea.** Software cheap win under soft_battle: the raster loops the bbox
today; many tris have sparse coverage (p99 bbox 2754, max 73600 in census).
Walk edges / use coverage test so empty bbox pixels are not shaded. Optional:
reject degenerate / zero-area early; skip offscreen after clip.

**Why it might win.** Census: 346906 bbox px × ~15 ns/px ≈ 5 ms desktop;
coverage is often ~half for right triangles — **partial** win, not 2×.
Large near-screen quads gain little. Still free under soft_battle with
**low image risk** if the coverage test matches current rules.

**Risk.** Subtle pixel diffs if edge rules diverge; easy to get wrong on
PS1 inclusion rules. Will not alone hit 60 Hz if present or other costs
dominate.

**Effort.** 0.5–1 day for a measurable spike (flag + Fight-menu census).

**vs all-black.** Independent soft-path win.

**Order.** **Spike #1 (soft track)** alongside E or instead of E if threading
is scary.

### I. Present-path wins (profile `present_us` vs raster)

**Idea.** Soft battle still packs RGB555 → GLES every frame. Dirty rects
already exist for partial upload — verify Fight-menu idle actually uses them
and that we are not full-packing 1024×512 or the whole display band when only
UI dirty. Split nxlink counters: `raster_us` (software push) vs `present_us`
(pack+tex+blit+swap). Optimize the larger bucket first.

Creative variants:

- Keep a persistent RGBA8 mirror of the display band; only convert dirty
  rects.
- Dual-buffer present: map/unmap or `glTexSubImage` subrects only.
- Avoid an extra CPU clear+composite when soft_battle is ON (opaque path
  already — confirm no mesh discard cost leaks).

**Why it might win.** preview.10 mesh path showed `present_us` ~0.58–0.68M
even when upload_us→0 — present can dominate. Soft path may hide similar
tax. If raster is 70% of frame, H/E matter; if present is 50%+, GPU mesh is
not the only lever.

**Risk.** Low image risk. Wrong dirty accounting → tearing/stale UI.

**Effort.** 0.5 day instrumentation; 0.5–2 days for the hot fix.

**vs all-black.** Independent; also tells us whether re-enabling mesh can
ever win if present stays ~0.6 ms+/frame.

**Order.** **Day-0 of any spike** — numbers before heroics.

### J. Size-gated GPU (big tris only)

**Idea.** Under FIGHTSTG, send only triangles with bbox area ≥ N (e.g. 256
or 1024) to GPU; tiny tris stay software. Census: median bbox 35, p90 803,
p99 2754 — **most fill is in the fat tail**. Offloading p90+ alone may remove
a large fraction of pixels with far fewer GL draws.

**Why it might win.** Best “bang for buck” hybrid once any GPU colour works.
Keeps UI/sprites software; small mesh details that stress CLUT stay on the
known-good raster.

**Risk.** Seams where GPU and software disagree (dither/filter). Threshold
tuning per scene.

**Effort.** 1 day after solid colour works.

**vs all-black.** Needs A/B colour first; then a strong FPS experiment.

**Order.** After A solid/untextured; before full textured cutover.

### K. No black-discard composite — mesh writes into CPU VRAM band (or reverse)

**Idea.** preview.9/10 pain was mesh FBO + UI discard. Alternatives:

1. GPU render → `glReadPixels` into the display band of CPU VRAM once per
   frame, then **opaque** present only (software UI drawn after readback, or
   UI drawn before GPU into a stencil/mask).
2. Or: software UI first into VRAM; GPU mesh with depth/stencil to protect
   UI — usually harder.
3. Or: two opaque layers without discard — mesh never covers UI rects
   (scissor UI regions out of mesh).

**Why it might win.** Removes discard shader bugs that punch holes and the
“black FBO ⇒ blue/black screen” failure mode. Opaque blit path is the one
we trust (preview.8).

**Risk.** Readback can be **slower** than soft fill if done naïvely (full
320×240 RGBA every frame). Must be a PBO/async or rare path. Scissor-UI
needs knowing UI rects.

**Effort.** 1–2 days for scissor/opaque composite once colour works; readback
spike 1 day to measure.

**vs all-black.** Explains owner “blue/black” even when FBO might have had
colour on the wrong band. Dump both bands before choosing.

**Order.** Alongside A’s composite rung (after solid colour).

### L. Shaderless / “CPU expands, GPU blits quads” (span atlas)

**Idea.** Extreme hybrid: software walks edges but only emits **opaque spans**
or small rect lists into a dynamic texture atlas; GPU draws textured quads
(or `GL_TRIANGLES` of screen rects) without PS1 CLUT in the shader. CLUT
resolved on CPU into RGB555/RGBA when building spans.

**Why it might win.** Moves ROP/blend to GPU; CPU does the hard PS1 texel
decode it already knows. Avoids the broken ES3 CLUT shader entirely.

**Risk.** Span generation cost may equal RasterTriangle. Atlas growth /
fragmentation. Semi-trans harder.

**Effort.** 3–5 days experimental.

**vs all-black.** Sidesteps the sample shader — useful if A textured stays
black after solid works.

**Order.** Contingency if A CLUT remains black after untextured works.

## Recommended next spike (1–2 days)

**Name:** “Colour before FPS” + “soft cheap wins”

**Track GPU (primary learning):** Approach **A/B ladder rung 1–2** only.

- Debug NRO: `-DDW3_NX_MESH_SOFT_BATTLE=OFF` plus a **compile-time**
  `DW3_NX_MESH_SOLID=1` (or env) that forces FragColor = vertex colour /
  constant magenta for every enqueued battle tri.
- Deferred dump (≥2000 prims) of `dump_mesh_fbo.ppm` **and**
  `dump_mesh_fbo_y0.ppm`.
- Present temporarily: mesh-only or opaque blit of mesh band — **no**
  black-discard UI for this spike (Approach K lite) so a black UI cannot
  hide a live FBO.

**Track soft (primary feel, shippable):** Approach **I** then **H**.

- Instrument Fight-menu idle: mean `raster_us`, `present_us`, `frame dt us`.
- Implement bbox coverage / edge walk behind a flag; measure again.

**Falsifiable done-when (either is success for the spike):**

1. **GPU track:** deferred Fight-menu dump shows
   `mesh_nonblack > 10%` of the 320×240 display band (or clear solid magenta
   covering the stage rect) with soft OFF + solid shader; **or**
2. **Soft track:** Fight-menu idle mean `frame dt us` ≤ **1.05e6** on OLED
   stock clocks with soft ON (≈ ≥57 Hz), field still ~1.00e6 opaque blit; **or**
3. Soft track partial: ≥15% reduction in mean `frame dt us` vs current soft
   baseline on the same device/build family, with owner visual OK.

If (1) fails (still black): stop textured work; debug viewport/FBO/band only;
consider Approach L later. Do **not** chase atlas/deko3d.

If (1) passes but FPS worse than soft: keep soft default ON; proceed to D/J/C
before any preview cut.

**Out of spike scope:** field mesh, ABR perfection, deko3d, release tags,
upstream PSY-Z PR, movie pacing, overclock.
