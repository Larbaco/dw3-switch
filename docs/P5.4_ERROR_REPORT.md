# P5.4 — Error reporting research (2026-10-16; table updated 2026-10-23)

Re-derives what already exists for P5.4, compares the reporting options, and
fixes the minimal path to the done-when: **a forced fault produces a readable
report on SD**. The implementation notes live in
[P5.4_CRASH.md](P5.4_CRASH.md); the preview.26 hardware evidence is in
[PREVIEW26_CRASH_RECORDS.md](PREVIEW26_CRASH_RECORDS.md).

## What happens today when the `.nro` faults on hardware

Verified live by preview.26 (both mechanisms produced files on the owner's
SD), and consistent with switchbrew (SVC → *Exception handling*,
*Fatal services*, *Error Report services*) and the Atmosphere module docs:

1. **Fault taken.** A user-mode exception (data/instruction abort, and also
   `svcBreak` with the panic reason) hits the faulting thread, in any of our
   threads. The kernel stores the registers into that thread's TLS
   (*UserExceptionContext*) and — for homebrew NRO code — takes the
   user-handled path back **to the process entrypoint** (crt0) unless the
   fault's address is itself readable executable memory (KDebug/creport path).
2. **libnx crt0** detects the non-zero error descriptor and jumps to
   `__libnx_exception_entry` (`nx/source/runtime/exception.s`), which guards
   two things: no `__libnx_exception_handler` defined → abort handling; the
   process is being debugged and `__nx_exception_ignoredebug == 0` → abort
   handling. Otherwise it pivots SP to `__nx_exception_stack`, copies a
   `ThreadExceptionDump` into `__nx_exceptiondump`, and returns from the
   exception into the tiny `__libnx_exception_returnentry` stub.
3. **We** override the weak `__libnx_exception_handler` with a bigger stack
   (0x4000 vs 0x400) and `__nx_exception_ignoredebug = 1`, so the handler also
   runs during nxlink/gdb sessions. Our handler (`nx_crash.c`) writes
   `sdmc:/switch/dw3/crash_report.txt` with raw `fsFileWrite` (no stdio, no
   fsdev locking) and then re-raises with `svcBreak` so the system-level path
   also gets a shot. A re-entry guard `svcBreak`s again if the report itself
   faults, so we cannot loop.
4. **Atmosphere creport** collects the crash and writes
   `sdmc:/atmosphere/crash_reports/<number>_<program_id>.log`
   (module-relative PC/LR/stack offsets, plus JPEG screenshots next to it),
   and uploads nothing. **Atmosphere fatal** draws its own register/backtrace
   error screen (code `2168-0006`) and may also write
   `sdmc:/atmosphere/fatal_reports/`. Without a handler override in our
   `.nro`, steps 2–3 reduce to the abort path and the same creport/fatal
   output still happens — but with none of our fields (version, mode/stage)
   and nothing we control.

Handling-abort semantics: if user-mode handling aborts (no handler, or the
handler itself cannot run), the kernel replays the exception into
crash-reporting; creport still captures it. A data fault inside readable
executable memory skips our handler entirely (KDebug path) — creport is then
the only report. Both were observed on preview.26: the creport logs named
`dw3-switch + offset` addresses with an extra `User Break`/`break reason 0x0`
marker from our re-raise, and our own `crash_report.txt` held
`reason: user exception`, mode/stage 0x166/0x1e1, and `ESR 0x92000007`.

## Options compared

| Option | Verdict |
|---|---|
| **1. libnx user-mode handler → our SD report → re-raise `svcBreak`** (landed 2026-10-12) | **Keep.** Only option that puts version + last mode/stage id in a file we own, before anything else runs. Report survives even if the system path fails. |
| 2. Atmosphere creport only (no handler override) | Complementary, not sufficient: catches every fault (including faults our handler cannot take), but the log names nothing we control (no version, no mode/stage) and its location/timestamps are Atmosphere's. |
| 3. `fatal:u` fatal throw (libnx `fatalThrow`) | Rejected. libnx's default policy is `ErrorScreen`, which writes **no** report; the report policy needs `fatalThrowWithPolicy` + a hand-built `FatalCpuContext`, and Atmosphere's fatal module *prevents* error-report creation while drawing its own screen. Worse readability for more work. |
| 4. Periodic marker file in the frame loop + startup latch | Rejected for crash detection: per-frame SD writes for data the crash handler already captures at fault time. The landed startup latch (rotate `crash_report_prev.txt` + log the previous reason/mode/stage) covers the "previous run crashed?" need with zero steady-state I/O. A marker would only add hang detection (no exception is raised when the loop wedges) — that belongs to P10.2 lifecycle work, not P5.4. |
| 5. On-screen assert overlay | **Still open** (the last roadmap line of P5.4). Not needed for the done-when: the report is pulled from SD, not read on screen. Sketch: reuse the HUD glyph renderer (`nx_debug_overlay.c` font atlas) to draw a small red-padded panel with the last `psyz_log` warning/error lines, hooked where errors are logged, drawn from the present path. Needs present-path iteration + hardware checks — do not hand-roll it as part of the report work. |

## Data the report should carry (status when this note landed)

| Data | Status | Where |
|---|---|---|
| NRO version | landed | `crash_report.txt` (`version:`) |
| Reason + `error_desc`/`ESR` names | landed | `reason:`, `error_desc:` |
| Last mode/stage overlay ids | landed (overlay latch) | `mode_file:`, `stage_file:` |
| PC/LR/SP/FP/FAR/pstate/x0/x1 | landed | same file |
| **Frame-loop liveness: vsync pumps + last 60-pump dt** | landed 2026-10-16 (`dw3_nx_crash_note_vsync`, two-word store per pump) | `vsync_pumps:`, `last_dt_us:` |
| Log tail | landed 2026-10-23 (P5.4 PR 1): the last 64 `psyz_log` lines from a lock-free ring in `nx_log.c` (our `psyz_log` implementation), plus a `CRASH` marker appended to `dw3.log`. Supersedes the earlier "do not embed a tail" call: `dw3.log` showed no error line for the preview.30-rc6 crash | `--- last log lines ---` in the report; marker in `dw3.log` |
| Stack trace / symbolizable addresses | landed 2026-10-23 (P5.4 PR 1): `module_base`, `base+0x…` offsets, validated frame-pointer backtrace, `git` + GNU `build_id`; `tools/symbolize_crash.py` resolves them with the matching `.elf` (also rebases older reports from the creport log) | report `#NN` lines; `sdmc:/atmosphere/crash_reports/*.log` still complementary |
| Previous run crashed? | landed 2026-10-16 (install rotates the old report to `sdmc:/switch/dw3/crash_report_prev.txt` and logs `previous run crashed: version=… reason=… mode_file=… stage_file=…`) | prev file + `dw3.log` |
| On-screen assert overlay | open (option 5) | — |

## Forced fault — how to run the done-when test

The build passthrough landed in `tools/build_switch_game.sh`:

```bash
./tools/build_switch_game.sh --nxlink --force-crash
```

(soft default OFF; the CMake option `DW3_NX_FORCE_CRASH` is unchanged for
direct-configure users — the original recipe in
[P5.4_CRASH.md](P5.4_CRASH.md#how-to-force-a-fault-debug-build) still works.)

1. Upload the nxlink NRO (hbmenu **Y** NetLoader, then `nxlink -a <ip> -s`).
2. Boot it once. After SD + path init it deliberately null-writes. The fault
   is expected *before* any overlay restore, so `mode_file`/`stage_file` are
   often `0x0` and `vsync_pumps: 0`.
3. Expected output, readable **without nxlink**:
   - `sdmc:/switch/dw3/crash_report.txt` (our report, complete field list);
   - a fresh `sdmc:/atmosphere/crash_reports/<ts>_<pid>.log` (Atmosphere),
     naming `dw3-switch` + offsets, `2188-…`/`2168-0006` fatal screen in
     between;
   - `sdmc:/switch/dw3/dw3.log` truncation marker: `previous run crashed:` on
     the *next* boot, with the live report preserved as
     `crash_report_prev.txt`.
4. Acceptance = the forced fault run ends with a report whose fields are all
   present and explainable (this is the P5.4 done-when). Then delete the
   dev-only NRO; release/preview builds never set the flag.

Emulator note: P5.4_CRASH.md originally accepted "hardware or Ryubing with a
mirrored sdmc:". Ryubing's emulation of the kernel exception path is
unverified, so treat **hardware as the truth** for the done-when; a Ryubing
run is bonus evidence only.
