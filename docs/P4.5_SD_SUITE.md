# P4.5 — SD suite plan (research note)

2026-10-16, branch `research/fs-log-sd` @ `6a02919` (preview.28 era, P6.9 owner
checks on `main`). The P4.5 CDFS acceptance is already **closed**:
[ROADMAP.md](ROADMAP.md) ticks it and [P4.5_STATUS.md](P4.5_STATUS.md) records
host evidence. This Note re-derives that status from current code, then works
out what an **on-device** suite record would take (owner-decision item), and
records the timing/logging half of P4.5 as it stands in the linked image.

## Status re-derivation

- `tools/cdfs_suite.c` is pure host C (stdio/stdlib/sys_stat) over
  `port/cdfs/cdfs.c` (stdio only, plus a `CLOCK_MONOTONIC` helper behind the
  `dw3: … us=` debug timings). It has two modes:
  `--self-test WORKDIR` (writes its own mini fixture, then path-reject +
  map/read/`read_at`/LBA checks) and `--root DIR` (packed tree). Exit 0 only
  with 0 `FAIL`s.
- `tools/tests/test_cdfs_suite.py` always runs the self-test; a packed run is
  added when `runtime/us`, `runtime/eu`, `DW3_CDFS_ROOT`, or `DW3_SD_RUNTIME`
  exists (owner-data paths stay skipped in CI).
- On the Switch, nothing else mounts data: `nx_file.c` mounts `sdmc` and
  everything reads plain stdio under `sdmc:/switch/dw3/<ver>/`
  ([RUNTIME_LAYOUT.md](RUNTIME_LAYOUT.md)). `romfs:` has no code users (repo
  grep: docs and `.gitignore` mentions only).
- Every hardware boot already enforces much of the suite passively:
  `dw3_runtime_ensure()` (`port/cdfs/runtime_extract.c`) stats the map,
  executable, `boot_tim.bin` and **every mapped file** before the game boots,
  and CDFS validates the map identity and file sizes. Boot logs
  `runtime version=… root=…` and `cdfs root=…` reach `dw3.log` + nxlink.
- Preview.4+ boots (P4.7) are the `sdmc:` open/read/list evidence for the same
  layout; the current preview line (26+) boots from that SD tree every run.

So "P2.5's cdfs tests pass against the SD layout" is met for the acceptance
by the mounted-tree path documented below. What is *not* on record anywhere:
a suite execution **inside** the console process reading the SD the game
reads. The next sections say whether that is worth doing and how.

## Options for an on-device suite record

| Option | How | Benefit | Cost / risk | Verdict |
|---|---|---|---|---|
| **A/B (accepted)** | No console change: run `cdfs_suite --root` against the tree the card uses — mount the card on a Linux box (or FTP/copy `switch/dw3/<ver>` out via Sphaira TCP 5000) | Formal 0-fail record over the *same bytes* the game reads; zero dev risk; both US and EU | Disk shuffle is manual; record is host-side only | **The formal acceptance path** (already in `P4.5_STATUS.md`) |
| **(a) gated in-.nro mode** | Build `--nxlink` + bake `DW3_NX_TEST_ENV="DW3_CDFS_SUITE=1"` (the existing `apply_test_env()` path). A small boot runner calls `cdfs_suite_main()` (lib mode, landed below): `--self-test sdmc:/switch/dw3/cdfs_selftest` then `--root <DW3_RUNTIME>`, logging each `OK/FAIL` to nxlink and a summary line through `psyz_log` into `dw3.log` | Same C assertions running *inside* the console against the real SD; permanent, one-flag; no new artifact on releases; runs before game init so a failure cannot be masked by game state | ~1 runner file + a boot_main hook + CMake condition, all dev-gated; needs an nxlink (or at least dw3.log) capture for the record | **Recommended when the owner wants an on-device record.** Prep landed (lib mode + host tests); switch-side patch is a sketch in this doc until a devkitA64 build machine validates it |
| **(b) NRO assets romfs fixture** | `elf2nro --romfs=fixture` on a test build + `romfsInit()` + `--root romfs:/fixture` | Zero-SD hardware run of the mini fixture | Build-side tool glue; diverges from how the game actually reads (sdmc); owner tree still needs the card; keeping a fixture romfs out of release NROs is another footgun | Rejected: `--self-test` already synthesizes its fixture (mkdir/`fopen` on sdmc), so (b) buys nothing; also `romfs` never proves the `sdmc` path the game uses |
| **(c) separate suite .nro** | Second, single-purpose CI artifact (`dw3-cdfs-suite.nro`) | Could ship prebuilt to owners | 4th packaging permutation + release README discipline for a tool the owner will run once per card swap; code duplicates (a) | Rejected; revisit only if owners (not the owner) request it |
| **(d) nxlink-hosted harness** | Host drives reads "over nxlink" | none found | nxlink is output-only by protocol; no file service; big verifies still need SD or console memory | Rejected; documented as a dead end |

## Recommendation

1. Keep **A/B** as the formal, recorded acceptance for SD changes (card
   layout, exFAT vs FAT32, new pack). Save suite stdout or the pytest log
   under the evidence folder per the machine rules.
2. If the owner wants a natively-recorded run (fresh console, docked
   hand-off, post-crash sanity): build the **(a)** mode from the sketch below
   on a devkitA64-capable machine; development-gated, never a release
   artifact; not a roadmap re-opening of P4.5.
3. Timing (VSync/RCnt) — current state is correct-by-construction plus the
   cheap standard check; see "Timing" below. No new code required.
4. Logging — already complete (three sinks, rate discipline in
   `docs/NXLINK_DEBUG.md`). No new code required.

## Acceptance criteria

Aligned to the roadmap done-when ("formal P2.5 CDFS suite passes against the
packed P1.6 tree — PC `runtime/<ver>` or Switch SD `…/switch/dw3/<ver>`:
map load, path reject, file-id read, `cdfs_read_at`, `cdfs_lookup_lba`"):

- **C1 self-test**: `cdfs_suite --self-test <tmp>` (or pytest with no
  packed root) exits 0 with `, 0 fail`.
- **C2 packed PC tree**: `--root runtime/<ver>` for **both** US and EU exits
  0 (skipped out-of-band until the owner tree exists, never faked).
- **C3 packed SD tree**: the same command against a mounted/copied
  `…/switch/dw3/<ver>` exits 0, for at least the version the run pinned
  (`runtime version=` + `cdfs root=` lines from the matching boot should be
  attached in the record).
- **C4 (optional, on-device)**: with the (a) mode built, `dw3.log` ends
  `cdfs suite: summary N ok, 0 fail` for self-test + the active root, both
  versions checked in-loop (`DW3_RUNTIME` falls back to
  `DW3_DEFAULT_RUNTIME`, so EU builds check EU automatically).

Status: C1 ✓ always (CI + local); C2 ✓ recorded in P4.5_STATUS.md (US; EU
when `runtime/eu` exists); C3 available any time by A/B; C4 pending the (a)
patch — blocked only on a devkitPro machine and an owner hardware pass.

## How to run

### A/B (today; PC side)

```bash
# from the repo root, with a packed or copied card tree
gcc -std=c11 -Wall -Wextra -O2 \
  -o build/cdfs_suite tools/cdfs_suite.c port/cdfs/cdfs.c -Iport/cdfs
./build/cdfs_suite --self-test /tmp/cdfs-self
./build/cdfs_suite --root /media/…/switch/dw3/us   # mounted/copied SD

# or, recorded through pytest (same binary the CI style uses):
DW3_SD_RUNTIME=/media/…/switch/dw3/us
DW3_CDFS_ROOT=/media/…/switch/dw3/eu  # second region, if wanted
python3 -m pytest tools/tests/test_cdfs_suite.py -v
```

Retain both stdout logs. Budget: samples=8 by default (`--samples` to raise
for a deeper pass); reads capped at 1 MiB per file (`--max-full`) so the run
finishes in seconds over FTP.

### (a) switch sketch (pending build machine; not landed)

Per-call counters, stdout reuse and the entry point are **already landed**
(`tools/cdfs_suite.c` lib mode; host shims
`tools/testdata/cdfs_suite_lib_main.c` mirror the runner's usage in
`tools/tests/test_cdfs_suite.py`: output identical to the CLI, and reusable
in one process). What remains is the switch-side glue:

```cmake
# platforms/switch/CMakeLists.txt (guarded like DW3_NX_FORCE_CRASH)
option(DW3_CDFS_SUITE "Compile the formal CDFS suite into the dev NRO (development only)" OFF)
if(DW3_CDFS_SUITE)
  target_sources(dw3-switch PRIVATE
    "${PROJECT_SOURCE_DIR}/tools/cdfs_suite.c"
    "source/cdfs_suite_runner.c")
  target_compile_definitions(dw3-switch PRIVATE
    DW3_CDFS_SUITE=1 DW3_CDFS_SUITE_LIB=1)   # suite entry: cdfs_suite_main
endif()
```

```c
/* platforms/switch/source/cdfs_suite_runner.c (sketch) */
#include "../psyz_backend/nx.h"   /* psyz_log */
#include <stdio.h>
#include <stdlib.h>
#include "cdfs.h"

int cdfs_suite_main(int argc, char **argv);

int dw3_cdfs_suite_run(const char *runtime_root);

int dw3_cdfs_suite_run(const char *runtime_root) {
    const char *on = getenv("DW3_CDFS_SUITE");

    if (on == NULL || on[0] == '\0') {
        return -1; /* not requested; boot the game */
    }
    INFOF("cdfs suite: begin root=%s self=sdmc:/switch/dw3/cdfs_selftest",
          runtime_root);
    {
        char *sv_args[] = {(char *)"cdfs_suite", (char *)"--self-test",
                           (char *)"sdmc:/switch/dw3/cdfs_selftest"};
        int self_rc = cdfs_suite_main(3, sv_args);
        char *rt_args[] = {(char *)"cdfs_suite", (char *)"--root",
                           (char *)runtime_root};
        int root_rc = cdfs_suite_main(3, rt_args);

        INFOF("cdfs suite: self rc=%d root rc=%d (0 == all OK)", self_rc,
              root_rc);
        return self_rc != 0 ? self_rc : root_rc;
    }
}
```

```c
/* platforms/switch/source/boot_main.c (sketch) — after dw3_nx_log_open()
 * and the nxlink banner, before dw3_nx_gpu_init()/init_paths(): */
#if DW3_CDFS_SUITE
    if (getenv("DW3_CDFS_SUITE") != NULL) {
        int suite_rc = dw3_cdfs_suite_run(env_or("DW3_RUNTIME",
                                                 DW3_DEFAULT_RUNTIME));
        ERRORF("cdfs suite: summary rc=%d (0 == all OK)", suite_rc);
        return suite_rc == 0 ? 0 : 1;
    }
#endif
```

Build + record on a Docker/devkitPro machine (the switch build is normally
`tools/build_switch_game.sh`; test env and extra options go through CMake,
as `build_switch_game.sh` does not forward them — same override style as
`docs/NXLINK_DEBUG.md`):

```bash
cmake -S platforms/switch -B build/switch-nxlink \
  -DCMAKE_TOOLCHAIN_FILE="$DEVKITPRO/cmake/Switch.cmake" \
  -DDW3_NXLINK_STDIO=ON -DDW3_CDFS_SUITE=ON \
  -DDW3_NX_TEST_ENV="DW3_CDFS_SUITE=1"
cmake --build build/switch-nxlink
# hbmenu Y NetLoader → nxlink -a <IP> -s build/switch-nxlink/dw3-switch-nxlink.nro
#   | tee /mnt/windows/Jogos/dw3-switch/tmp/evidence/cdfs-suite-<date>.log
# also archive sdmc:/switch/dw3/dw3.log (Sphaira FTP TCP 5000)
```

Either toggle works alone: the compile gate (`DW3_CDFS_SUITE=ON` → no game
in that dev NRO) or the baked env (`-DDW3_NX_TEST_ENV=…` keeps the game and
runs the suite only when baked). Baking both as shown is the belt-and-
braces default: the dev NRO cannot ship the suite mode, and an ordinary
`--nxlink` rebuild without the env still boots the game.

Expectations: the NRO boots straight into the suite (no game), prints the
same `OK …` / `FAIL …` lines the host CLI does, and exits with a nonzero
code on any failure (hbmenu shows "app closed"; the `dw3.log` summary line
is the durable evidence either way). The self-test path needs **no SD
runtime** — that is why option (b)'s romfs fixture buys nothing. The
self-test workdir (`sdmc:/switch/dw3/cdfs_selftest`) is disposable scratch;
delete it if you want the card clean.

### Timing (VSync/RCnt) — status + cheap verification

State (no change needed):

- The game's only timing primitives are `VSync` (boot sequence
  `VSync(0)` ×4 + one `VSync(3)`) and the per-frame `GFX.vsync` via
  `VSyncCallbacks` (`display.c`). RCnt has **zero decomp callers**; PSY-Z's
  RCnt shim (PS1 clock units, µs conversion) would arm only if a future
  patch registers `InterruptCallback(IRQ_RCNT0..2)` — at which point it
  should be re-reviewed for the dot-clock conversion and the
  `MIN_PERIOD_US` clamp (`kernel.c`).
- On Switch, `VSync(0)` maps to `Psyz_VideoVSync(0)`: present + block on
  `eglSwapBuffers` with `eglSwapInterval(1)`, then `Psyz_KernelVBlank`
  dispatches the game's vsync callbacks. `VSync(n>1)` paces one frame
  instead of n — the known limitation behind the one-line boot warning;
  the game path that triggers it is a single boot-pacing call.

Cheap standard check (existing instrumentation; no new code):

```text
From any hardware nxlink run (any preview), grep "frame dt us=":
  60-pump window should be 1_000_000 µs ± ~2%.
preview.7 reference: mean ≈ 1.017 s / 60 frames (~59 FPS), a few
1.5 s windows — battle raster backlog, not timer drift.
```

A window outside ±2% means the present no longer blocks on vblank (i.e.,
the eglSwapInterval contract broke) — a real defect worth logging, and 60
windows of history sit in the same lines. RCnt drift cannot fail because
nothing consumes RCnt.

### Logging — status

`nx_log.c` fans each `psyz_log` line to (1) stderr → nxlink, (2)
`sdmc:/switch/dw3/dw3.log` (truncate-per-boot, `fflush` per line so crashes
keep their reason), (3) `svcOutputDebugString` (the live channel inside
emulators; a no-op syscall on hardware). Retail `lm`/`nn::diag`-style
logging is stubbed and homebrew `lm:get` does not exist — do not chase it.
Retrieval and rate discipline live in `docs/NXLINK_DEBUG.md`.
