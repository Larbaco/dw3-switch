# P5.3 — Flat save host (2026-10-11)

## Landed

- Runtime save format is **one flat file per port** (`save0.bin` /
  `save1.bin`, 32 KiB) under the existing memcard directory, resident in
  RAM. `MemCardReadFile` / `MemCardWriteFile` are `memcpy` at offset.
- Flush is deferred: one rename-atomic write when a write section ends
  (next non-write `MemCard*` call) or on `memcard_host_shutdown`.
  Write goes to `saveN.bin.tmp`, then `remove(saveN.bin)` + `rename`
  (FAT/exFAT and Windows reject rename-over-existing with EEXIST).
- `MemCardGetDirentry` returns synthetic `size = 0x8000` when a save
  exists. `MemCardExist` / `MemCardAccept` do not walk directory frames.
- One-time migration from this port's `memcardN.mcr` → `saveN.bin` by
  DW3 product name (US/EU/JP), with the image renamed to `.mcr.bak` only
  after a successful extract. Corrupt/wrong-size `saveN.bin` is
  quarantined as `.bad` so migration can still run.
- PC and Switch hosts register `atexit(memcard_host_shutdown)` and call
  shutdown if `dw3_game_main` returns.
- No in-game emulator card import/export (P9.6 stays a separate tool).

## Still open

- **HOME / `appletMainLoop`:** Switch vsync deliberately does not call
  `appletMainLoop` (it blocked the frame). `Psyz_QuitRequested` still
  returns 0. A HOME kill does not run `atexit`, so an in-progress write
  burst that never hit a non-write `MemCard*` call can lose dirty RAM.
  Wiring a non-blocking quit/focus path is follow-up (also P10.2).
- Sleep / focus-loss flush and time-delta clamp are not part of this
  change.
- Hardware: preview.11 OLED migrated both slots (`memcardN.mcr` →
  `saveN.bin` + `.mcr.bak`) and Continue loaded the slot. Still need a
  **second** boot after clean exit to confirm reload without remigrate.

## OLED preview.13 — EEXIST flush (2026-10-11)

In-game SAVE on flat `save0.bin` / `save1.bin` logged
`memcard flush FAILED ... (File exists)` then `STGMCARD_writeSave ...
status=3` (cartão bloqueado). Cause: `rename(tmp, saveN.bin)` on Switch
SD (FAT/exFAT) when the dest already existed; `flush_failed` left the
card looking locked for the rest of the session. Fix: unlink dest before
rename. On-disk `saveN.bin` from that session should still be the last
*successful* flush (pre-failed write); reboot after the fix clears the
runtime lock — do not FTP-delete saves.

## OLED preview.14 — MC1 load → MC2 save (2026-10-11)

Tip `1af94ef` (#82) on OLED + SD. Owner loaded MC1 (`save0.bin`) slot0
at money=50, spent in-session, saved to MC2 (`save1.bin`) slot2.
nxlink: `STGMCARD_writeSave port=1 slot=2 status=1` with no
`flush FAILED`. FTP pull of both flats: MC1 slot0 still 50/progress=4;
MC2 slot2 money=26/progress=4 (checksum OK). Cross-port overwrite flush
PASS. Continue from MC2’s third slot for the spent state.

## Out of scope here

- P9.6 external `.mcr` ↔ flat converter under `tools/`.
- Rewriting `STGMCARD` or other decomp save logic.
- Restoring data-frame XOR on byte `0x7F`.
