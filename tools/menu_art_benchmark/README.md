# CPU-only menu artwork benchmark

This isolates `dw3_pc_title_overlay_art` from the game and GPU. It needs
Python 3, Git, a Linux C compiler and libm; no game assets, submodule checkout,
display, Switch connection or clock changes. It measures host x86 code,
**not Switch frame time or FPS**.

Run from any directory, using a new output directory outside this checkout:

```sh
python3 tools/menu_art_benchmark/run.py --out /tmp/dw3-menu-art-results
```

A short smoke run, including untimed pixel-call counters:

```sh
python3 tools/menu_art_benchmark/run.py --out /tmp/dw3-menu-art-smoke \
  --cold 2 --warm 3 --optimizations O2 --count-pixels
```

`--out` is required, must not exist, and must resolve outside this repository
(including symlinks). Output remains available after temporary sources and
executables are removed. No files under the checkout are written by the runner.
Failed runs may leave a partial output directory; use a new path when retrying.

## Sources and workloads

The runner extracts only `title_overlay_art.c`, `title_overlay_art.h`,
`title_overlay_labels.inc` and `title_overlay_lettering.inc` with `git show`
into a temporary directory. The defaults intentionally pin the historical
comparison, even after PR #170 has merged:

- `--main-sha 4b2068fc451e86952e1495c62b96a96427f651f1`: before PR #170.
- `--pr170-sha b43be1be87d8a6612abaceb5d31c0112784df3c6`: reviewed PR #170.

Those commits must already exist locally; the runner does not fetch. Override
the arguments to compare other commits with the same artwork API. Metadata
records resolved commits and hashes of the four extracted files. Compilation
uses `--cc cc` by default, `-O2` and `-O3`, `-D__SWITCH__` and `-lm`.
The Switch define selects button hints and wording, **not AArch64 code**.

Each optimization level compares:

- Baseline five states: Press Start, three menu selections, options.
- Baseline options only (control workload).
- PR #170 options only, matching its partial-update path.

Each canvas is 960×720 RGBA, 2,764,800 bytes; the five-state buffer is
13,824,000 bytes. Every draw includes the host's redundant pre-clear plus the
generator's own clear. Setters run outside the timer. Cursor cycles through
three rows, boolean values toggle, and turbo cycles 2x/3x/4x.
Built-in English masks and the default footer are used. Disc-captured EU
letter masks are absent, so the title batch does not reproduce exact EU art.

## Timing and outputs

`CLOCK_MONOTONIC_RAW` measures drawing only. Allocation, output and the final
checksum are outside the timer. A final checksum keeps generated bytes live.
Cold means the first draw in each of 25 fresh processes: it includes initial
buffer page faults, but not process startup, and does not flush hardware/OS
caches. Warm means 200 draws in one process after discarding its first draw.
`--cold` / `--warm` change sample counts. Frequency, affinity and scheduling
are left unchanged; cases run sequentially, so host load can affect tails.

- `results.json`: counts, median, p95, maximum and buffer size.
- `*-raw.json`: cold/warm samples in milliseconds and final buffer checksum.
- `metadata.json`: source hashes, commits, flags, compiler, host, harness hash.
- `counts.txt` with `--count-pixels`: separate untimed instrumentation.

p95 selects sorted index `floor(.95 * (n - 1))`; very small smoke samples are
only functional checks. Pixel counters count calls rather than unique pixels,
with default cursor 0 / all options OFF. Instrumentation changes only a
temporary copy and fails if the expected `pixel` signature has changed.

These results exclude uploads, GPU work, driver synchronization, gameplay,
SDL, capture and present. They support choosing what to prototype, not an
OLED performance claim. The preserved initial experiment is under
[`docs/evidence/menu-art-cpu-2026-10-15`](../../docs/evidence/menu-art-cpu-2026-10-15/README.md).
